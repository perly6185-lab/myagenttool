# “我的站点”产品与实施规划

状态：实施版 v0.19（五阶段体验收口、云平台安全连接、SSH 自托管、响应式图片、案例向导与双语内容发布已完成）；v0.20 自有服务器域名与证书管理阶段 1–3 已实现，真实 AliDNS staging 验证待用户凭据
首要用户：需要维护个人或小团队官网、但不想管理服务器和 CMS 的普通用户
产品入口：MyAgentTool 一级工作入口“我的站点”

## 当前实现状态（2026-08-26）

已完成：站点与页面版本模型、团队隔离、普通建站向导、页面/文章区块编辑、主题与品牌色、安全静态预览、显式发布计划、不可变版本、本地原子发布、健康验证、上一版本恢复，以及“我的设置”中的全局普通/专业模式和站点专业设置。Cloudflare Pages Direct Upload 与阿里云 OSS + CDN 均已接入真实 API。阿里云适配器包含 V4 签名客户端、Bucket/版本控制/静态网站/CDN/HTTPS 前置检查、不可变整包上传、入口对象切换、CDN 刷新轮询、线上首页 SHA-256 核对和历史版本恢复。

阿里云与 Cloudflare 首次连接现已支持“代码先就绪、配置后填写”：桌面端通过 Electron `safeStorage` 使用操作系统安全存储分别加密 AccessKey，以及 Cloudflare Account ID/API Token；站点状态只保存 `credential://aliyun/main` 或 `credential://cloudflare/main`。桌面进程使用独立随机令牌把解密后的凭据注入服务端进程内存，内部接口只写不读，不进入 JSON/SQLite 状态、HTTP 读模型或日志。两个平台使用独立加密记录和撤销通道，移除一方不会影响另一方；没有安全存储时失败关闭，浏览器模式仍可使用环境变量产生的既有凭据引用。

v0.20 阶段 1 已新增独立 AliDNS 安全连接：SSH 自托管专业设置显示“域名与 HTTPS · 阿里云 DNS”，桌面端把 RAM AccessKey 加密为独立记录并只向服务端进程注入 `credential://alidns/main` / `alidns_acme`。AliDNS、阿里云 OSS 和 Cloudflare 三套记录可独立保存、恢复和撤销，provider 与引用错配会失败关闭。

v0.20 阶段 2 已新增独立 `SiteDomainTlsBinding` 持久化模型和 API：绑定 SSH 发布目标、规范化域名、公网/局域网访问方式、固定 AliDNS DNS-01 引用、证书生命周期状态、续期时间与脱敏失败摘要。局域网模式只允许绑定已显式开启私网策略的已验证主机；发布目标或域名变化会使现有绑定进入重新检查状态。普通视图只显示“域名已保存、HTTPS 待完成/需要处理/已启用”等业务状态，专业视图才显示 DNS 提供商、挑战类型和 revision。

v0.20 阶段 3 已实现 AliDNS `DescribeDomainRecords` 只读验证和 Let’s Encrypt staging DNS-01 签发器。执行器使用公共后缀规则在本地确定托管根区，签发前检查 CAA，只允许固定 staging directory；临时 TXT 在可见后完成挑战，并在成功、失败和超时路径都按本次 RecordId 删除。清理失败只保留 RecordId 的 SHA-256 摘要并进入 `needs_attention`。AccessKey、TXT value、ACME 账号私钥、证书私钥和 PEM 均不进入 JSON/SQLite、HTTP 响应或事件日志；测试证书与账号密钥暂存于当前进程内保险库，进程重启后需要重新执行 staging，不能用于自动续期或服务器部署。当前代码尚未使用用户真实凭据发起外部验证。

发布过程具备可轮询进度。普通用户只看到“准备文件—上传网站—更新线上网站—验证上线”，专业视图额外显示适配器阶段、对象数量和更新时间；阿里云 CDN 刷新期间每秒刷新状态，并明确提示可能需要数分钟。失败恢复阶段会说明正在恢复上一健康版本。

图片素材已形成普通用户闭环：编辑页面时可按需上传 PNG、JPEG 或 WebP，直接给首屏、图片集和站点标志选图；服务端按文件签名校验、限制单文件/站点容量、按内容去重，原始字节独立进入受管私有存储。可解码图片自动生成不放大的 480/960/1440 px WebP 版本，静态页面通过 `srcset`、`sizes`、宽高属性和延迟加载按设备选择；用户可在普通编辑器用左右/上下滑杆调整裁剪焦点。原图始终保留，派生失败、超时或旧素材没有派生图时自动回退原图。图片解码和缩放运行在有超时与输出上限的隔离子进程，损坏图片不能带崩站点服务。预览与生产发布读取同一份字节，发布快照绑定素材 revision、焦点和派生资源，草稿或任一历史发布仍引用的素材不能误删。普通视图隐藏指纹与存储引用，专业设置可查看 MIME、体积、状态、指纹和包含派生图的总用量诊断。

案例创建已形成普通用户向导：用户只需依次填写案例名称与一句话成果、背景与做法、最终成果，再按需选择封面和正文图片；系统自动生成安全页面地址、结构化详情区块和联系行动入口，不要求理解 slug 或区块协议。首个案例会原子地在首页加入动态“精选案例”，后续案例自动出现且不会重复创建首页模块。保存后立即打开真实草稿预览，但不会自动发布；发布确认会分别列出新增案例和首页修改。向导明确提醒只填写已获公开许可的信息，离开未保存表单会二次确认。

双语内容已进入同一套普通维护与发布闭环。专业用户只在“我的设置”开启中英双语；普通用户回到“我的站点”切换正在维护的内容语言，对未翻译页面创建翻译草稿。默认语言继续使用原 URL，第二语言使用 `/en/` 或 `/zh/` 独立目录。翻译草稿保留图片、邮箱、电话和安全链接，但不会复制原语言可见正文；标题和摘要完成后进入现有页面编辑器继续翻译。缺失翻译不会出现在第二语言导航、文章列表或案例列表，站内行动按钮也不会跳回另一种语言。发布产物包含按页面生成的 `hreflang`、`x-default`、语言切换和双语站点地图。

普通用户审核后的高优先级问题已经修复：本地版本与公网线上版本使用不同状态，不再把本地发布显示为“当前线上”；没有公网地址时提供按访客区域选择的上线引导，并明确把真实云账号配置交接到“我的设置”。文章列表会生成可点击的文章卡片，新增文章发布后可以从首页和文章页访问。页面和新文章存在未保存修改时，关闭或取消会二次确认；普通编辑器不再展示网址名称。发布按钮在没有修改时禁用，确认页显示具体内容名称与业务化发布位置，发布失败优先使用普通语言说明旧网站是否受影响。预览支持桌面和 390 px 手机视图，站点样式页可以直接上传并应用 Logo。

SSH 自托管已成为生产可用适配器。专业用户在“我的主机”验证主机身份、SFTP 原子能力和专用 `site_publish` 文件范围，再在站点专业设置选择该范围与 HTTPS 域名；站点不会复制主机凭据。发布使用不可变目录、逐文件远端回读、原子 `current` 切换、固定公网地址的 TLS 首页核对和失败恢复，历史回滚由范围外受管回执约束。v0.20 已加入 staging DNS-01、独立 `tls_certificate` 范围、证书原子部署、固定 Docker Nginx 动作和失败恢复；主机管理员仍需预先准备专用目录、容器挂载与 staging CA，正式证书和自动续期留在下一阶段。Cloudflare 首版要求使用已经存在的 Direct Upload Pages 项目；阿里云首版要求使用已经存在并完成静态网站、版本控制、CDN 和 HTTPS 配置的专用 Bucket。项目自动创建以及备案自动配置继续留在后续阶段。

真实 Linux 主机联合验收使用独立的环境记录承载设备地址和分阶段证据，不作为本地站点 MVP 的依赖。SSH/SFTP、应用级范围绑定和内网发布通过后，再使用专用测试子域名、DNS-01 和独立 443 服务验证内网可信 HTTPS，不要求先开放公网入口。

内网先行链路现已完成首次发布、二次发布和恢复，验证了真实 SFTP 上传、逐文件回读、原子 `current` 切换和内网页面内容变化。该结果不把内网 HTTP 标记为公网可用；正式生产目标继续要求可信 HTTPS 与公网地址核对。

当前仍未实现站点名称、全局页脚的逐语言覆写，以及自有服务器的正式证书持久保险库、部署、激活和续期。AliDNS/ACME staging 自动化已实现但尚未使用真实用户凭据验证；案例、文章、页面、翻译和图片均已进入同一套草稿、预览、发布与恢复协议。

## 五阶段体验收口（v0.9）

### 1. 发布状态与任务引导

“我的站点”提供持续可见、可收起的四步任务卡：内容已准备、检查网站预览、发布最新内容、访客可以访问。任务卡根据草稿、有修改、本地版本和已上线四种业务状态自动选择下一步操作；保存与发布继续严格分离。普通用户可以随时收起步骤，收起后仍保留完成数量和当前状态。

### 2. 真实上线配置向导

上线引导分为三个普通问题：访客区域、平台网址或自有域名、自己配置或交给技术人员。中国大陆选项明确提示 OSS + CDN 与 ICP 备案边界，不承诺自动备案。向导只通过会话级交接记录传递推荐平台和用户选择，不包含账号、AccessKey、Bucket 或域名；专业设置读取交接后展示摘要并预选推荐托管方式，所有真实配置仍保持空白，直到用户或技术人员主动填写。

### 3. 失败恢复

发布失败统一说明失败版本是否公开、当前健康版本是否仍在服务，并按错误类型只给出一个主要恢复方向：重新检查并发布、检查上线设置，或恢复上一健康版本。普通视图隐藏错误码；专业视图额外显示经过清理的错误码和 HTTP 状态。图片上传对超限、格式不支持、文件内容与扩展名不一致、数量和空间上限提供可执行说明。

### 4. 移动端、键盘和无障碍

顶部预览和发布按钮在窄屏下平分可用宽度；390 px 管理界面必须保证关键操作不越出视口。预览宽度使用真实 390 px iframe。重复的页面操作带页面名称，任务卡与上线选择公开 `aria-expanded`、`aria-pressed` 和明确控件名称；Logo 选择和上传保持独立语义。任务卡、向导、编辑、发布确认和恢复支持键盘操作与焦点恢复。

### 5. 三角色验收

自动验收使用隔离真实服务端和 Chromium，不写入真实云配置：

| 角色 | 必须完成的流程 | 自动验收证据 |
| --- | --- | --- |
| 普通建站者 | 创建站点、理解四步任务、桌面/手机预览、首次发布 | 真实浏览器流程与 390 px 边界断言 |
| 内容维护者 | 只改页面标题、识别未发布状态、二次发布、恢复上一版 | 真实服务端发布和恢复流程 |
| 技术配置人员 | 接收大陆/自有域名交接、进入阿里云清单、确认配置为空 | 专业设置浏览器流程与无凭据断言 |

正式发布仍需安排真实用户可用性测试，记录首次建站完成率、日常维护独立完成率、上线状态判断正确率和失败恢复成功率。自动化测试负责防止已确认流程回归，不能替代真实用户样本。

## 小范围真实用户试用（v0.10）

受控试用入口通过试用批次生成的 `?sitePilot=<匿名批次码>&pilotTask=<任务>` 链接开启，普通访问不显示试用面板；`?sitePilot=1` 仅保留给本机手工验证。参与者必须先明确同意，才会创建团队隔离的试用会话；可以在任务中途撤回并删除本次记录。系统仅保存任务类型、允许列表内的里程碑、选择题结果、1–5 分易用度和时间，不保存页面正文、标题、网址、自由文本、参与者账号标识、AccessKey、Bucket、域名或其他云平台资料。批次链接只开放对应邀请的临时试用站点，不授予正式站点权限。

三项主指标统一只以已结束任务为分母，进行中的会话单独展示但不提前计入失败：

- 建站完成率：已记录“站点创建成功”的首次建站任务 / 已结束的首次建站任务。
- 独立维护成功率：实际记录到“内容保存成功”，并同时选择“完成任务”和“无需他人代操作”的内容维护任务 / 已结束的内容维护任务。
- 上线状态理解率：正确区分“仅预览”“已有本地版本”“公网可访问”的状态判断任务 / 已结束的状态判断任务。正确答案由服务端根据站点实际状态计算，客户端不能自行上报答对。

“我的设置 → 站点专业设置”只展示团队聚合结果、样本量和明确分母；分母为 0 时显示“—”，不伪装成 0%。自动化浏览器流程只验证采集与计算链路，不进入真实用户指标；当前仍需邀请真实参与者完成受控任务后，才能形成可用于产品决策的结果。

## 试用运营与决策闭环（v0.11）

专业视图可以一键创建匿名试用批次，无需预先填写参与者名单或真实配置。每个批次可以为首次建站、独立维护和上线状态理解按需生成任务锁定的一次性邀请链接。系统默认每类任务目标为 5 个已结束样本，三项指标门槛均为 80%；这些是首轮保守默认值，后续可根据试用规模调整。

批次只显示聚合进度，不提供参与者明细：

- 任一任务样本不足时，批次状态为“继续采集样本”，不提前判断通过或失败。
- 三类任务均达到样本目标且三项指标均达到门槛时，显示“本轮达到门槛”。
- 三类任务均达到样本目标但任一指标未达到门槛时，显示“进入体验改进”。
- 结束批次会阻止新会话，但保留聚合结果；删除批次会在二次确认后同时删除该批次的全部匿名记录。

同一团队一次只允许一个采集中的批次，避免多个链接造成分母混淆。批次码不是认证凭据，服务端仍按当前登录身份和团队边界授权；其他团队即使获得批次码也无法加入或读取结果。

## 试用数据质量控制（v0.12）

共享批次链接已经替换为一次性匿名邀请，避免同一链接被重复提交而污染小样本指标：

- 每次生成的邀请只绑定一个批次和一种任务，不记录姓名、邮箱、账号 ID 或其他参与者身份。
- 邀请在参与者同意并开始任务时原子消费；已开始、已完成或已放弃的链接均不能再次创建会话。
- 同一团队可以通过不同邀请链接并行开展多场试用；页面只根据当前链接恢复对应的进行中任务，不会串到其他参与者会话。
- 参与者完成或放弃后，邀请状态同步进入终态；撤回并删除记录时，会话和对应邀请一起删除。
- 批次按任务展示“邀请总数—已开始—已结束”漏斗。未使用邀请不进入三项成效指标分母，但能暴露邀请转化和样本缺口。

一次性邀请仍不是登录凭据，也不扩大正式站点权限。邀请原始码只在专业视图生成后显示；服务端始终同时校验当前团队、批次状态、任务类型和邀请是否已使用。

## 邀请级隔离试用沙箱（v0.13）

每个一次性邀请同时创建一个独立、可清理的临时站点空间。服务端验证当前团队和邀请原始码后，才把 `/api/sites` 请求映射到该邀请专属的匿名临时团队；不携带试用上下文的请求仍只读取正式团队站点，两类数据不能互相查询或修改。

- 首次建站任务获得空白空间，不受团队已经存在正式站点的限制；多个参与者可以重复完成首次建站。
- 独立维护任务自动生成不含真实资料的示例官网；参与者的保存、预览和本地发布仅写入该邀请空间。
- 状态理解任务按“已有本地版本、仅预览、模拟公网可访问”循环分配夹具，保证小样本内三种状态相对均衡；正确答案绑定邀请夹具，由服务端计算。
- 沙箱只列出本地发布能力。配置或验证 Cloudflare、阿里云 OSS + CDN、SSH 等外部目标时服务端固定拒绝，不读取凭据解析器，也不调用真实云 API。
- 邀请空间默认 72 小时后过期；撤回试用、删除批次、再次访问试用入口或读取运营汇总时，会清理已过期临时站点的页面修订、素材、发布计划、发布版本和本地发布目录，正式站点保持不变。
- 未开始的过期邀请单独计入“已过期”漏斗，不进入成效指标分母；进行中的任务到期后按未完成结束，避免活动会话永久占用样本状态。
- 邀请原始码只在生成链接的响应中返回一次，持久化状态仅保存 SHA-256 摘要；服务端兼容读取升级前已存在的旧邀请。
- 前端站点缓存按邀请代码分区，避免同一浏览器先后打开正式站点和试用链接时复用错误缓存；试用面板持续提示当前为临时环境。

## 试用任务易用性优化（v0.14）

普通用户模拟发现，独立维护沙箱最初没有已发布基线，导致只修改一个标题时仍显示 5 项初始内容等待发布，无法准确验证“独立完成一次日常维护”。当前维护沙箱会先自动生成仅供预览的本地基线版本；参与者保存一次首页标题修改后，只显示 1 项未发布修改。基线不会连接公网或使用真实云配置。

三类试用任务现在都在开始前和进行中持续显示约 2 分钟的两步操作说明，明确必填项、完成标志以及是否需要发布。独立维护保存成功后，工作区就近提示“本次任务不需要发布”，并提供返回试用面板提交结果的按钮，减少长页面回找操作的阻力。

## Cloudflare 桌面安全连接（v0.15）

专业设置中的全球云托管不再要求桌面用户手工配置环境变量。用户可以填写 32 位 Cloudflare Account ID，以及仅授予 Pages 编辑权限的 API Token；Electron 使用操作系统安全存储加密后，只把不透明引用写入站点配置。保存成功后输入框立即清空，界面只能看到连接状态和 `credential://cloudflare/main`，不能回读 Token。

Cloudflare 与阿里云凭据均通过同一个受桌面随机令牌保护的内部只写接口进入服务端进程内保险库，但服务端会同时校验提供商与引用命名空间，阻止交叉错配。用户可以独立移除 Cloudflare 连接；保存、恢复或移除失败时不会把明文凭据写入状态或响应。浏览器模式继续只接受已有凭据引用，并可通过环境变量解析。

当前 Cloudflare 首版仍要求 Pages Direct Upload 项目已经存在。用户在专业设置填写项目名称，保存发布目标后运行“测试连接”，由真实适配器核对 Token 权限和项目可访问性；项目自动创建留在后续平台自动化阶段。

## 响应式图片与安全焦点调整（v0.16）

上传成功后不要求普通用户理解压缩格式或尺寸。系统保留原图，并在容量预算内生成 480、960、1440 px WebP；小图不会被放大，尺寸落在档位之间时额外保留原始宽度的 WebP。派生图也计入站点容量、发布清单和删除清理范围。

首屏与图片集使用响应式候选图，原图作为永久兜底。普通用户点击素材卡即可看到 16:9 裁剪预览，通过“左右位置”和“上下位置”调整主体焦点；焦点是素材级设置，会同步影响该图的所有裁剪展示。保存焦点后明确形成 1 项未发布图片修改，发布确认页显示“图片展示位置”，不会把已经保存但尚未上线的变化误报为线上效果。

图片解码放在独立工作进程中并设置 30 秒超时与 64 MB 输出上限。签名正确但内容损坏的文件即使触发底层解码器异常，也只会失去自动优化能力；原图上传、其他草稿和主服务进程保持可用。普通接口不返回原图或派生图的存储键，派生 SHA-256 只在专业视图可见。

## 普通用户案例创建向导（v0.17）

“页面与文章”顶部提供独立的“添加案例”，与“写新文章”并列但不新增一级栏目。向导固定为三步：基本信息、过程与成果、图片与确认。前两步只收集访客真正需要理解的内容；页面地址、内容区块、详情布局和行动入口自动生成。第三步允许复用素材库或直接上传图片，没有图片也能继续。

保存动作同时创建案例详情草稿，并在首次创建时给首页增加一个动态案例展示区块。两项写入位于同一服务端事务，失败时不会留下只有详情、没有入口的半成品。第二个及后续案例复用同一首页区块，由确定性渲染器生成标题、摘要和详情链接。案例归档后会从动态展示和站点地图中移除。

向导最后展示背景、做法、成果和图片摘要，主按钮明确写为“保存并预览”。保存成功后打开生产同源渲染预览，顶部仍显示未发布修改；只有用户再次进入发布确认并确认，案例才进入新版本。自动验收覆盖首次案例、后续案例不重复首页区块、详情渲染、首页可发现性、发布差异和完整浏览器发布流程。

## 双语内容维护与隔离发布（v0.18）

双语属于站点能力设置，因此只在专业视图开启；翻译属于日常内容维护，因此放在普通视图。开启后内容列表出现“正在维护的内容语言”，切换语言不会改变管理界面语言，也不要求用户理解语言代码或 URL 前缀。未翻译项继续显示原页面名称作为定位参照，并明确标记“未翻译”，主操作只有“创建中文版”或“创建英文版”。

创建翻译草稿分两层完成：第一层只填写翻译标题和摘要；第二层复用普通页面编辑器翻译其余可见内容。系统复制区块结构、图片引用及安全联系方式，清空标题、段落、按钮文案、图片说明等原语言文本，避免用户误把未翻译内容公开。翻译和原文通过稳定关系关联，禁止同一页面同一语言出现两份翻译，页面地址冲突按语言独立校验；已经存在该语言内容时不能直接关闭语言能力，防止静默丢失入口。

静态发布保持默认语言向后兼容：首页仍为 `/`，其他页面仍为 `/<slug>/`；第二语言首页为 `/en/` 或 `/zh/`，详情页位于对应语言目录。导航只使用同语言翻译，动态文章和案例列表也只读取当前语言。内部行动链接会解析为同语言目标；目标未翻译时不输出跨语言按钮。每组已翻译页面输出语言切换、`hreflang` 和 `x-default`，每种已启用语言生成独立 404 页面，站点地图包含所有实际存在的语言页面。

当前双语首版不自动机器翻译，也不为全局站点名称和页脚维护语言覆写；这两项作为后续增强，避免在没有审核的情况下生成可能错误的公开文案。自动验收覆盖双语开启、普通用户创建安全翻译草稿、独立 URL、导航缺失翻译隔离、动态列表隔离、站内链接隔离、语言元数据、站点地图、重复翻译和关闭语言保护。

## 1. 产品目标

在 MyAgentTool 中提供一套从内容维护到官网发布的完整闭环：用户可以维护首页、关于、服务、案例、文章和联系方式，先预览变化，再把一个可追踪、可回滚的版本发布到自己的域名。

首版解决三个核心问题：

1. 官网信息分散，修改一次需要找代码、找文件或找外包。
2. 发布结果不可预期，用户不知道哪些内容将公开、是否发布成功。
3. 历史版本难以恢复，误改后没有简单可靠的回滚手段。

产品承诺：

- 内容维护不要求用户理解 Git、构建命令、对象存储或 CDN。
- 草稿不会因为保存而自动公开。
- 每次发布前都能看到变化范围和完整预览。
- 每次成功发布都生成不可变发布版本，可以回滚到上一个健康版本。
- 对外站点与 MyAgentTool 管理后台隔离，官网故障或攻击不直接扩大到控制平面。

## 2. 首版假设与边界

### 首版假设

- 一个团队先管理一个站点，数据模型保留多站点扩展能力。
- 中文为主要内容语言，页面和数据模型支持后续增加英文版本。
- 站点以品牌展示和内容发布为主，不包含交易、会员和复杂互动。
- 用户沿用现有 MyAgentTool 身份登录后台。
- 对外站点采用静态发布快照；后台不直接暴露给公网访客。

### 首版不做

- 在线商城、支付、订单、会员和权限社区。
- 任意 HTML、JavaScript 或第三方脚本注入。
- 多人复杂审核流和字段级权限。
- 评论系统、在线客服和自建表单处理服务。
- 全功能拖拽页面搭建器。
- 自动生成并直接发布 AI 内容。
- 多站点、多品牌和多语言发布。

联系入口首版使用邮箱、电话、社交链接或外部预约链接。自建联系表单涉及反垃圾、隐私数据、通知可靠性和合规，放到后续独立阶段。

## 3. 信息架构

### 对外官网

| 页面 | 目的 | 首版内容模块 |
| --- | --- | --- |
| 首页 | 让访客快速理解“你是谁、提供什么、下一步做什么” | 主视觉、简介、核心服务、精选案例、最新文章、行动按钮 |
| 关于 | 建立可信度 | 个人/团队介绍、经历、价值观、里程碑、头像或团队照片 |
| 服务 | 解释可提供的能力 | 服务卡片、适用对象、交付方式、常见问题、联系入口 |
| 案例 | 展示结果 | 案例列表、案例详情、背景、过程、成果、相关素材 |
| 文章 | 持续发布信息 | 文章列表、分类、文章详情、发布日期、作者、分享元信息 |
| 联系 | 提供明确下一步 | 邮箱、电话、社交账号、地址、预约或外部表单链接 |
| 隐私说明 | 说明数据边界 | 隐私政策、站点统计和第三方服务说明 |

导航由用户配置，但首页、文章详情、隐私说明和 404 页面由系统保证基础可用性。

### 管理后台“我的站点”

默认普通视图只保留三个工作区域，不再为每项能力增加栏目或全局导航：

- 网站首页：网站地址、线上状态、尚未发布的修改、最近发布结果和高频快捷操作。
- 页面和文章：首页、关于、服务、案例、文章和联系信息统一维护。
- 网站样式：Logo、预设主题、品牌色、字体、网站菜单和页脚。

“预览”和“发布网站”是页面顶部或底部固定操作，不单独占一个栏目。“图片和文件”在用户选择封面、插图或下载文件时按需打开，不把素材库作为普通用户必须理解的独立目的地。“恢复上一版”出现在最近发布结果和发布失败恢复区域。

建议将“我的站点”注册为 `entry/ordinary` 一级工作入口。现有一级工作入口已经较多，“我的站点”上线时应通过真实导航测试决定是否直接常驻，或在用户创建站点后才固定显示。普通视图中不出现构建、托管、适配器、revision、指纹、DNS、canonical 或 JSON-LD 等专业术语。

### 普通视图与专业视图规范

产品采用一套全局双视图规范，站点不再创建第二个独立模式：

1. 所有用户默认使用普通视图，完成建站、编辑、预览、发布和恢复不需要开启专业视图。
2. “我的设置 → 使用偏好”提供一个全局“使用模式：普通视图 / 专业视图”，现有“专业任务视图”迁入这套统一规范，不与站点模式并列成多个开关。
3. 开启专业视图后，站点全局专业内容统一出现在“我的设置 → 站点专业设置”；“我的站点”日常页面仍保持简洁，只在必要处提供带当前上下文的“高级设置”入口。
4. 专业视图是展示偏好，不是权限模型。API 仍根据身份和站点权限授权，不能依赖隐藏界面保障安全。
5. 关闭专业视图只隐藏专业信息，不删除高级配置，也不改变线上站点。
6. 指向专业页面的深链接在普通视图下回到对应普通页面，并说明可在“我的设置”中切换使用模式。
7. 切换模式不丢失当前站点、页面、筛选和编辑位置；返回时恢复用户原来的工作上下文。

| 能力 | 普通视图 | “我的设置”中的专业视图 |
| --- | --- | --- |
| 内容编辑 | 标题、摘要、封面、正文、分类和页面区块 | 页面地址、canonical、重定向、结构化数据和内容 revision |
| 外观 | Logo、预设主题、品牌色和字体方案 | 主题变量、资源覆盖和渲染诊断 |
| 搜索展示 | 自动生成并预览搜索标题与摘要，可选择修改 | SEO 模板、索引策略、站点地图和 JSON-LD 详情 |
| 网站地址 | 显示域名状态和一步步修复引导 | DNS 记录、证书、解析诊断和域名验证详情 |
| 发布 | “发布网站”、修改摘要、进度和结果 | 发布目标、适配器、构建清单、幂等键和远端核对 |
| 历史恢复 | “恢复上一版”及影响摘要 | 完整版本历史、产物指纹、验证记录和指定版本回滚 |
| 素材 | 图片预览、说明、使用位置和替换 | MIME、尺寸、派生资源、内容指纹和清理保留策略 |
| 故障处理 | 普通语言原因和可执行下一步 | 技术诊断、执行回执、健康检查与审计关联 |

专业设置按任务分组，不做技术字段堆叠：

- 搜索与链接：SEO、URL、重定向和结构化数据。
- 域名与发布：域名验证、发布目标、凭据连接状态和发布策略。
- 外观细节：主题变量和高级资源配置。
- 版本与诊断：完整发布历史、健康检查、构建记录和审计证据。

首次连接域名时，普通用户仍通过“我的站点”中的引导向导完成；只有手动 DNS 配置和故障诊断进入专业设置，不能以“请开启专业视图”阻断普通用户主流程。

页面地址、单页搜索展示、重定向等“属于某一页”的高级配置虽然展示在“我的设置”体系中，但必须从当前页面携带 `siteId` 和 `entryId` 直接打开；不能要求专业用户离开文章后再从全站设置中搜索原对象。

## 4. 核心用户流程

### 4.1 首次建站

```text
打开“我的站点”
  -> 用一句话填写“网站叫什么、给谁看、希望访客做什么”
  -> 选择一个基础模板并填写公开联系方式
  -> 立即生成可编辑的网站预览
  -> 按“还差什么”清单补充 Logo、服务和介绍
  -> 选择“先预览”或“发布到临时地址”
  -> 首次发布时连接推荐的发布位置
  -> 查看将公开的页面和联系方式并确认
  -> 显示网站地址和下一步“绑定自己的域名”
```

首次设置不要求域名、DNS 或备案信息。用户可以先在本地完成内容和预览；全球托管目标可先提供平台临时地址。主要面向中国大陆且选择中国内地托管时，在发布前明确说明自定义域名和备案前置条件，不伪装成可以立即上线。

### 4.2 修改官网信息

```text
进入概览或内容列表
  -> 打开页面草稿
  -> 编辑结构化模块
  -> 自动保存草稿
  -> 查看桌面/手机预览
  -> 查看相对线上版本的变化
  -> 发布并验证
```

保存和发布必须是两个不同动作。编辑冲突通过 `expectedRevision` 返回可恢复的 409，不静默覆盖另一份更新。

### 4.3 发布文章

```text
新建文章或从本地资料库引用内容
  -> 编辑标题、摘要、封面、正文和分类
  -> 查看自动生成的搜索展示信息，按需修改
  -> 检查公开素材与外链
  -> 预览文章和文章列表
  -> 加入下一次站点发布
```

从本地资料库导入时只创建新的站点草稿并保留来源关系；本地原文仍是独立原始资料，后续变化不会静默改写已发布文章。

### 4.4 回滚

```text
在网站首页点击“恢复上一版”
  -> 查看将恢复的页面、文章和图片摘要
  -> 明确确认恢复
  -> 系统恢复上一个验证成功的版本
  -> 显示线上检查结果，当前草稿继续保留
```

普通视图只提供“恢复上一版”。专业视图可在“我的设置 → 站点专业设置 → 版本与诊断”选择任意健康历史版本。回滚只切换到历史不可变快照，不用当前草稿重新构建。草稿保留，方便修正后再次发布。

## 5. 内容编辑模型

首版内部采用“结构化区块 + 受限富文本”模型，不允许任意脚本和原始 HTML。Markdown 只作为导入/导出格式，不作为普通用户编辑器概念。

协议区块及普通用户名称：

- `hero` → 大标题：标题、副标题、背景图、主次行动按钮。
- `rich_text` → 文字介绍：标题、段落、列表、引用和安全链接。
- `service_cards` → 服务列表：服务名称、说明、图标和行动入口。
- `case_cards` → 案例展示：案例摘要和详情链接。
- `article_list` → 最新文章：最新文章或指定分类。
- `gallery` → 图片展示：图片、说明和替代文本。
- `metrics` → 关键数字：少量可验证数字及说明。
- `faq` → 常见问题：问题与回答。
- `contact` → 联系方式：公开联系方式和外部预约链接。
- `cta` → 行动按钮：一个明确行动目标。

编辑器要求：

- 页面由区块排序组成，支持新增、复制、移动、隐藏和删除。
- 每个区块有固定字段和长度提示，错误在字段附近解释。
- 默认编辑体验接近日常文档和页面预览，普通用户不直接编辑 Markdown、JSON 或区块协议名。
- 自动保存只进入草稿版本；离开页面前不丢内容。
- 桌面、平板和 390 px 手机预览使用与发布端相同的渲染器。
- AI 可以生成草稿、摘要、SEO 建议和替代文本，但必须由用户采纳，不能自动发布。
- 普通视图先展示内容和访客效果；页面地址、canonical、结构化数据等字段只在“我的设置”的专业视图中编辑，并保留当前页面上下文。

## 6. 数据模型

所有记录包含 `ownerTeamId`、`createdAt`、`updatedAt` 和审计主体；所有写操作使用期望 revision。

- `visibility`: `private_preview | public`
- `activePublicationId`

### SiteSettings

- 联系方式和页脚信息
- `revision`

### SiteEntry

- `id`, `siteId`
- `type`: `page | article | case`

- `publishedRevisionId`

- `seoTitle`, `seoDescription`, `shareAssetId`
- `revision`

### SiteEntryRevision

- `id`, `entryId`, `revisionNumber`
- 结构化 `blocks`
- 本次修改说明和创建主体
- 内容校验结果
- `createdAt`

revision 记录不可原地修改。自动保存可以合并当前工作草稿，但一旦进入发布快照即不可变。

### SiteAsset

- `id`, `siteId`
- 原始文件的不透明存储引用，不返回不受控绝对路径
- MIME、字节数、宽高、内容指纹
- 替代文本、说明、焦点位置
- `status`: `processing | ready | rejected | missing`
- 引用计数和来源关系

### SiteNavigation

- 顶部与页脚两个导航区
- 有序链接项：内部条目 ID 或经过校验的外部 URL
- `revision`

### SitePublication

- `id`, `siteId`, `version`
- 精确的设置、导航、条目 revision 和素材指纹清单
- 构建产物指纹
- `status`: `planned | building | uploading | verifying | active | failed | superseded | rolled_back`
- 发布目标、发起主体、确认记录、验证结果和时间戳
- 上一活动版本 ID，支持可解释回滚

### SiteDeploymentTarget

- `id`, `siteId`
- `kind`: `local_directory | cloudflare_pages | aliyun_oss_cdn | ssh_static`
- `providerAccountRef`、`remoteProjectRef`、region 和域名等非敏感配置
- `credentialRef`：本地凭据引用，不保存明文 Token/AccessKey
- `capabilities`：预览、原子激活、原生回滚、自定义域名、托管 HTTPS 和资源限制
- `status`: `setup | ready | needs_attention | disconnected | disabled`
- 最近验证时间、验证摘要、`revision`

### SiteDomainTlsBinding（v0.20 规划）

- `id`, `siteId`, `deploymentTargetId`, `hostname`
- `accessMode`: `public | private_lan`；私网模式只能绑定目标主机已经验证并固定的私网地址
- `dnsProvider`: 首版为 `alidns`，`dnsCredentialRef` 使用独立引用 `credential://alidns/main`
- `challenge`: 固定为 `dns-01`；状态只保存 ACME order URL 的摘要、证书指纹、SAN、签发者和有效期，不保存 challenge value
- `certificateScopeId`：指向主机上独立于公开站点根的 `tls_certificate` 范围
- `activationProfileId`：固定类型的 Web 服务重载配置；不接受自由 shell、容器参数或 Nginx 片段
- `status`: `setup | dns_ready | issuing | staging_ready | deploying | staging_deployed | active | renewal_due | needs_attention | disabled`
- `lastVerifiedAt`, `renewAfter`, `notAfter`, `revision` 和经过脱敏的最近失败摘要

ACME 账号私钥、证书私钥、AliDNS AccessKey 和临时 TXT challenge 均不进入该模型、普通状态、审计正文或 HTTP 读接口。

## 7. 技术架构

```text
apps/web “我的站点”后台
  -> apps/server 站点草稿、revision、发布计划与审计 API
  -> 受管素材存储
  -> 共享站点 schema / 安全渲染器
  -> 不可变静态发布包
  -> 发布适配器
  -> 静态托管与自定义域名
```

建议代码边界：

- `apps/web/src/features/my-site/`：内容维护、预览、发布和历史界面。
- `apps/server/src/routes/sites.mjs`：HTTP 路由，仅做输入解析和响应映射。
- `apps/server/src/services/sites/`：站点、条目、素材和发布领域服务。
- `packages/protocol/src/site.*`：共享 schema、状态枚举和 API 契约。
- `packages/site-renderer/`：确定性 HTML 渲染、SEO、站点地图、RSS 和资源清单。
- `tools/dev/site-release-smoke.mjs`：本地端到端发布与回滚验证。

关键架构决策：

1. 对外站点不是 `apps/web` 管理 SPA 的公开路由，而是独立静态产物。
2. 预览与生产发布复用同一个 schema 和渲染器，避免“预览正确、线上不同”。
3. 发布包内容寻址且不可变；激活版本是一个小而原子的状态切换。
4. 素材原文件不进 JSON 状态，不以 base64 保存；元数据和引用进入事务状态，字节进入受管存储。
5. 发布凭据遵循现有桌面凭据边界，控制平面只持有不透明凭据引用。
6. 首个真实发布适配器应保持单一；适配器契约稳定后再扩展其他托管平台。
7. 将现有专业任务偏好收敛为统一用户展示偏好 `experienceMode: ordinary | professional`；它不进入站点发布清单，也不改变服务端权限。
8. 专业设置复用“我的设置”页面体系并延迟加载，专业发布与诊断模块不进入普通站点页面的初始 Web bundle。

## 8. 发布位置与云平台策略

### 8.1 总体决策

官网是静态内容站，普通用户默认发布到静态托管平台，不要求购买或维护一台长期运行的云服务器。站点内容、渲染器和发布记录保持平台无关；每个云平台通过相同的发布适配器契约接入。

首版只允许一个活动发布目标，避免普通用户同时维护多个线上来源。更换平台必须走“迁移预览—双地址验证—域名切换—保留旧版观察期”的独立流程，不能把“更换平台”伪装成普通发布。

### 8.2 支持顺序

| 顺序 | 发布目标 | 产品定位 | 普通视图名称 |
| --- | --- | --- | --- |
| 1 | 本地目录 | 开发、测试、完整导出和备份；不直接提供公网访问 | 导出网站文件 |
| 2 | Cloudflare Pages Direct Upload | 首个真实云适配器，适合海外或全球访问和快速上线 | 全球云托管 |
| 3 | 阿里云 OSS + CDN | 主要面向中国大陆访客的正式发布目标 | 中国大陆云托管 |
| 4 | SSH/SFTP + Nginx | 已有 Linux 主机的专业用户选项 | 我的服务器 |

GitHub Pages 可以作为开发者扩展目标，但不作为普通用户默认项。它把网站发布与仓库、分支和自动化工作流绑定，和“普通用户无需理解 Git”的首版目标不一致。

如果产品首批真实用户明确以中国大陆访问为主，则 Cloudflare Pages 与阿里云适配器的业务优先级对调，但本地目录适配器仍先完成，用于验证渲染和发布协议。

### 8.3 Cloudflare Pages 首个真实适配器

选择 Direct Upload 模式，由 MyAgentTool 生成完整静态目录后直接上传，不把用户内容仓库暴露为必需依赖。Cloudflare Pages 官方支持上传预构建资源、平台临时地址、自定义域名、预览部署和生产版本回滚，和本方案的不可变发布快照较匹配：

- [Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/)
- [Custom domains](https://developers.cloudflare.com/pages/configuration/custom-domains/)
- [Cloudflare Pages](https://developers.cloudflare.com/pages/)

适配器必须处理平台文件数、单文件大小和域名配置限制；超过能力边界时在构建前拒绝并给出压缩、外部资源存储或迁移建议，不能上传一半后才失败。

普通用户首次连接只看到：

```text
选择“全球云托管”
  -> 在本机连接 Cloudflare 账号
  -> 选择现有项目或创建新网站
  -> 获得临时网站地址
  -> 发布并检查
  -> 以后绑定自己的域名
```

Direct Upload 与 Git 集成的项目类型差异由适配器处理；首版创建的项目明确使用 Direct Upload，不在界面承诺无损切换到 Git 集成。

当前凭据边界：站点只保存形如 `credential://cloudflare/main` 的引用。桌面端优先通过系统安全存储保存 Account ID/API Token，并在当前服务端进程中临时解密使用；浏览器或无桌面桥接环境从环境变量 `MYAGENTTOOL_CREDENTIAL_CLOUDFLARE_MAIN` 读取 JSON：

```json
{"accountId":"32 位 Cloudflare Account ID","apiToken":"仅授予 Pages Write 的 API Token"}
```

明文 Token 不进入站点状态、发布记录、HTTP 响应或事件日志。保存目标后必须先执行“测试连接”，目标状态变为 ready 后普通用户才可发布。部署失败会把计划标记为 failed，并保持原活动版本和公网地址不变。

### 8.4 阿里云 OSS + CDN 国内适配器

阿里云 OSS 支持静态网站托管；位于中国内地的 Bucket 绑定自定义域名时需要完成 ICP 备案。产品必须在用户选择“中国大陆云托管”时提前说明这一前置条件，而不是等发布失败后显示平台错误：

- [阿里云 OSS 静态网站托管](https://help.aliyun.com/zh/oss/user-guide/hosting-static-websites)
- [阿里云 CDN 接入](https://help.aliyun.com/zh/cdn/getting-started/quick-access-to-alibaba-cloud-cdn)
- [工信部 ICP/IP 地址/域名信息备案管理系统](https://beian.miit.gov.cn/)

国内适配器要求：

- 使用站点专用 Bucket，只存放已确认公开的发布产物，不与私有资料库、邮件或任务材料共用。
- 通过受限账号或角色授权，只授予目标 Bucket、CDN 配置和必要域名检查权限。
- 新版本先上传到隔离位置，完成链接和资源验证后再激活。
- 必须证明平台上的版本激活和回滚满足本方案的一致性要求；如果 OSS + CDN 组合无法可靠切换版本，该适配器不得标记为生产就绪，应增加蓝绿源站或其他具备版本部署能力的托管层。
- CDN 缓存刷新、域名解析和证书状态属于发布后的独立验证阶段，不把“已经上传”显示为“已经上线”。

当前实现采用以下发布协议：

1. “测试连接”核对 Bucket 区域、版本控制为 `Enabled`、静态网站首页/错误页为 `index.html`/`404.html`，并核对 CDN 域名在线、HTTPS 已开启、源站指向该 Bucket、域名只解析到公网地址。
2. 完整发布包上传到 `_myagenttool/releases/{publicationId}/`，对象设置一年不可变缓存；HTML 内部资源和站内入口引用绑定到同一不可变版本。
3. 将 HTML、sitemap 和 robots 等入口对象写到公开路径，根 `index.html` 最后写入；这些对象禁用缓存。随后提交 CDN 目录刷新并轮询任务到 `Complete`。
4. 从自定义域名重新读取首页并核对 SHA-256。只有远端内容与本次确认版本一致，发布记录才变为健康且活动。
5. 激活后任一步失败时，从上一健康发布的不可变前缀恢复入口对象、再次刷新 CDN 并独立核对首页；恢复本身失败则明确返回 `site_deployment_recovery_failed`，不伪装成功。

站点状态只保存凭据引用，例如 `credential://aliyun/main`。桌面端首选在系统安全存储中保存 AccessKey，并在当前服务端进程中临时解密使用。浏览器或无桌面桥接环境仍可从对应环境变量 `MYAGENTTOOL_CREDENTIAL_ALIYUN_MAIN` 读取 JSON：

```json
{"accessKeyId":"受限 RAM 用户或 STS 的 AccessKey ID","accessKeySecret":"AccessKey Secret","securityToken":"使用 STS 时可选"}
```

专业设置使用三步向导：安全连接、发布位置、上线检查。需要填写 Bucket 名称、形如 `oss-cn-hangzhou` 的公网区域和自定义 CDN 域名，然后保存并执行“测试连接”。所有字段可以稍后填写；系统不生成虚假默认值，也不会在配置不完整时尝试外部连接。AccessKey 不进入站点状态、发布记录、HTTP 响应或事件日志。

普通视图将备案显示为业务状态：

- 可以准备内容：继续编辑和本地预览。
- 等待网站备案：说明需要在云平台完成什么，以及完成后如何继续。
- 可以发布：域名、备案、证书和发布目标均已验证。

### 8.5 自有服务器

自有主机只在专业视图提供，通过 SSH/SFTP 上传到新的版本目录，由受控 Nginx 配置或符号链接完成切换。连接前必须验证目标目录不是系统根目录、用户主目录或未知共享目录；不得允许用户输入一段自由 shell 命令作为发布配置。

SSH 静态站点不单独建设主机连接和文件上传逻辑，而是复用“我的主机”的主机信任、受控文件范围、传输计划和传输凭证。完整开发分期、安全边界与 API 见 [“我的主机”受控连接与文件传输开发规划](MY_HOST_PLAN.md)。

首版自有主机能力至少包括：

- 主机指纹确认和最小权限账号。
- 限定发布根目录与路径穿越检查。
- 新版本目录、健康检查、原子切换和历史版本保留。
- 上传中断恢复和远端状态核对。
- 清理预览、明确确认和可配置保留数量。

#### 8.5.1 域名与可信 HTTPS（v0.20）

站点专业设置在选择 `ssh_static` 后增加“域名与 HTTPS”，按四步展示：

1. **网站域名**：填写完整主机名并选择“公网访问”或“仅当前局域网”。内网模式不要求发布公网 A/AAAA 记录；浏览器可通过内网 DNS 或本机 hosts 解析，应用健康检查则直接连接该 SSH 主机已经验证的固定地址，同时保留原域名的 TLS SNI 和 HTTP Host。
2. **DNS 授权**：首版接入 AliDNS，使用独立的 `credential://alidns/main`，不能复用或覆盖 OSS/CDN 的 `credential://aliyun/main`。桌面端安全存储分别加密两套凭据并允许独立撤销。
3. **证书与部署位置**：使用 ACME DNS-01 申请公开可信证书。证书版本写入主机独立 `tls_certificate` 范围，目录不位于 `<scopeRoot>/current`、不能被站点 Web 根访问，也不能通过普通文件下载功能导出私钥。
4. **上线检查**：核对证书链、SAN、有效期、TLS SNI、首页摘要、Web 根和重载状态；只有全部通过后才允许把 HTTPS 绑定标记为 `active`。

私网模式必须同时满足：主机已显式允许私网连接、地址与已确认 SSH 主机一致、证书主机名与站点域名一致、系统仍执行完整 CA 校验。禁止 `verify=false`、忽略证书错误、HTTP 降级、任意目标 IP 或把 RFC1918 地址伪装为公网就绪。

#### 8.5.2 AliDNS 最小权限与 ACME 生命周期

协议与权限依据：[Let’s Encrypt challenge 类型](https://letsencrypt.org/docs/challenge-types/)、[阿里云 DNS 自定义权限策略](https://help.aliyun.com/zh/dns/alibaba-cloud-dns-custom-permission-policy-reference-dns)。

- RAM 身份只授予目标域名上的 `DescribeDomainRecords`、`AddDomainRecord` 和 `DeleteDomainRecord`；连接测试必须用只读调用证明账号、域名和权限匹配。
- 首次签发先走 Let’s Encrypt staging，确认 TXT 创建、权威 DNS 可见和清理成功后，才允许用户确认正式签发，避免消耗生产速率限制。
- 每次 order 只创建本次 `_acme-challenge` TXT；验证结束立即按 RecordId 删除。删除失败时证书结果可以保留，但连接状态必须显示 `needs_attention` 和残留记录摘要。
- 签发前检查已有 CAA；不满足时只给出所需记录，不静默修改域名策略。DNS-01 不要求域名 A/AAAA 指向公网，也不会自动创建公网解析。
- 默认在到期前 30 天进入续期窗口；桌面进程启动和每日定时检查均可触发幂等续期。若应用长期未运行，专业视图和普通站点状态必须在到期前持续预警，不能声称后台服务仍在运行。
- 后续如引入常驻续期代理，必须使用短期身份或同等最小权限凭据、独立升级与撤销通道；不能把桌面 AccessKey 明文复制进通用容器环境。

#### 8.5.3 证书部署、激活与恢复

- 新证书先上传到不可变版本目录，文件权限按私钥 `0600`、目录 `0700` 收紧；逐文件回读仅核对公开证书与本地私钥的公钥匹配和摘要，不在日志中输出 PEM。
- 通过 `current` 指针原子切换完整证书版本，避免 `fullchain.pem` 与私钥来自不同版本。
- Web 服务重载只能选择管理员预先验证的固定 profile。首版支持专用 Docker Nginx profile；调用参数限定为已绑定容器 ID/名称和固定 HUP/reload 动作，不接受任意命令。
- 切换并重载后，从固定目标地址使用原域名 SNI 进行 HTTPS 验证。失败时恢复上一证书指针、再次执行同一固定重载并复验；恢复也失败则标记 `site_tls_recovery_failed`，停止内容发布并提示人工处置。
- 证书更新不自动发布内容，内容发布也不顺带更换证书；两者使用独立计划、确认、回执和回滚状态。

#### 8.5.4 实施顺序

1. 独立 AliDNS 凭据命名空间、Electron 安全连接器和只写注入 API。**已完成。**
2. 域名/TLS 数据模型、专业设置四步向导和私网固定地址验证策略。**模型、API、访问方式约束、已验证私网地址绑定和普通/专业状态入口已完成；签发执行时的重新解析固定与 SNI 核验将在执行层接入。**
3. ACME staging 签发器、AliDNS DNS-01 适配器、TXT 清理与脱敏测试。**代码与自动化测试已完成；真实 AliDNS/Let’s Encrypt staging 验证待用户凭据。**
4. `tls_certificate` 范围、证书原子上传、固定 Docker Nginx 重载 profile 和失败恢复。**代码与自动化测试已完成；真实主机仍保持未变更。**
5. 正式证书、自动续期调度、到期预警、真实内网主机回归和安全演练。

阶段 4 的 staging HTTPS 校验必须显式配置测试 CA，优先使用 `MYAGENTTOOL_ACME_STAGING_CA_FILE=/absolute/path/to/staging-root.pem`；也可使用 `MYAGENTTOOL_ACME_STAGING_CA_PEM`。CA 文件应从 Let’s Encrypt 官方 staging 文档获取。未配置时部署失败关闭为 `site_tls_staging_ca_required`，不会使用 `-k`、`rejectUnauthorized=false` 或系统生产信任库冒充测试链可信。

前四步完成前，产品不得把现有 OSS 凭据输入框描述为自有服务器证书配置，也不得把手工放置证书标记为“自动续期已开启”。

### 8.6 发布适配器契约

每个真实发布适配器必须实现同一能力集合：

```text
connect          连接账号或主机并保存不透明凭据引用
inspect          读取非敏感目标信息和能力限制
preflight        在上传前检查域名、配额、文件和权限
stage            上传新的不可变候选版本
preview          返回候选版本预览地址或受控预览能力
activate         将已验证候选版本切换为线上版本
verify           检查页面、资源、HTTPS、域名和平台状态
inspect-result   在超时或不确定结果后查询真实远端状态
rollback         重新激活一个已验证历史版本
cleanup-plan     预览可清理版本，不直接删除
disconnect       撤销连接但不擅自删除线上网站
export           导出平台无关的完整静态发布包和清单
```

适配器声明自身能力，例如 `previewUrl`、`atomicActivation`、`nativeRollback`、`customDomain`、`httpsManaged` 和 `maxAssetBytes`。不具备关键能力时，服务层负责安全补偿；无法补偿 `atomicActivation` 或可靠回滚时，不允许成为普通用户的生产发布目标。

### 8.7 凭据与账号边界

- 云平台授权在本机连接进程完成，优先使用浏览器授权；必须使用 Token/AccessKey 时，引导创建最小权限凭据。
- 明文凭据只进入操作系统凭据存储或现有桌面凭据进程，不进入站点状态、Web 表单回显、日志或发布清单。
- 服务端只保存 `credentialRef`、提供方、账号显示名、能力范围和最近验证状态。
- 断开连接默认不删除线上网站；删除云端项目是独立高风险动作，首版可以不提供。
- 发布前重新验证凭据与目标归属，防止账号或项目在用户确认后发生变化。

### 8.8 普通用户选择规则

普通视图不先问云产品名，而是问访问目标：

```text
访问者主要在哪里？
  - 海外或全球 -> 推荐“全球云托管”
  - 中国大陆   -> 推荐“中国大陆云托管”，提前检查备案条件
  - 已有服务器 -> 提示在“我的设置”切换专业视图
  - 暂时不确定 -> 先预览或导出，不阻断内容维护
```

任何自动推荐都必须显示实际提供方、数据将上传到哪里、可能产生的费用和如何断开连接，不能用“智能托管”隐藏供应商。

## 9. 发布协议

发布采用“计划—确认—执行—验证—激活”五步：

1. **计划**：服务端锁定候选 revision，生成新增、修改、删除和域名变化摘要。
2. **确认**：用户查看整站预览、断链、缺图、SEO 和可访问性检查，确认精确计划 ID。
3. **执行**：构建不可变静态包，上传到新的版本目录，不覆盖当前线上目录。
4. **验证**：检查首页、关键页面、资源、`sitemap.xml`、`robots.txt` 和响应状态。
5. **激活**：验证通过后原子切换活动版本；失败保持旧版在线。

以上是内部协议名称。普通视图只呈现“准备发布—确认修改—正在发布—检查网站—发布完成”，专业视图才显示精确状态、清单和执行证据。

发布计划绑定站点 revision、条目 revision、素材指纹和目标 revision。任一输入在确认后变化，旧计划失效并要求重新预览。

首版必须支持：

- 发布幂等键，重复请求不创建两个线上版本。
- 可取消的构建/上传阶段；激活阶段不可假装取消成功。
- 不确定结果进入 `verifying`，先查询远端状态，不盲目重试。
- 线上健康检查失败时保留上一活动版本。
- 每次执行记录普通用户可读摘要和技术诊断证据。

## 11. 安全与合规边界

- 所有导入正文、外链元数据和素材都是不可信输入，不作为代理指令。
- Markdown 和结构化区块输出统一转义并使用白名单协议；拒绝脚本、事件属性和危险 URL。
- 图片校验真实文件类型、大小和尺寸，生成受控派生图；SVG 首版按下载文件处理，不内联执行。
- 草稿预览默认需要登录；临时分享预览后续采用短期、可撤销、只读 Token。
- 发布目标凭据不进入 Web 页面、日志、发布清单或审计正文。
- 站点和发布记录按团队隔离，未知资源返回不可枚举结果。
- 自定义域名启用前验证所有权；域名变化单独显示在发布确认中。
- 隐私说明、统计脚本和 Cookie 行为显式配置；首版默认无第三方跟踪脚本。
- 删除内容不立刻删除仍被历史发布快照引用的素材；清理采用预览、确认和保留期。

## 12. SEO、可访问性与性能

每次发布自动生成：

- 每页唯一 title、description、canonical 和社交分享元信息。
- `sitemap.xml`、`robots.txt`、文章 RSS。
- 文章和组织/个人的基础 JSON-LD，字段不足时不生成猜测值。
- 语义化标题层级、键盘焦点、图片替代文本检查。
- 响应式图片、尺寸属性和延迟加载。

首版质量目标：

- 390 px 宽度无横向滚动，核心操作可键盘完成。
- 发布前阻断空标题、重复 slug、缺失内部链接目标和缺失关键素材。
- 普通页面首屏不依赖客户端 JavaScript 才能显示主体内容。
- 静态产物不存在管理 API 地址、凭据引用、内部 ID 或本地绝对路径泄漏。
- 1,000 篇文章规模下，增量发布和完整发布都有明确耗时预算并纳入基准测试。

## 13. 分阶段交付

### 阶段 0：产品契约与原型

- 固化单站点边界、信息架构、区块 schema 和发布状态机。
- 完成普通视图的概览、内容编辑、整站预览、发布确认、恢复上一版，以及“我的设置”中专业视图的桌面与 390 px 原型。
- 固化普通/专业能力矩阵、术语映射、偏好切换和专业深链接降级规则。
- 确定首个真实发布适配器和凭据边界。
- 为站点 schema、发布清单和错误语言建立契约测试。

退出条件：普通用户能在原型中完成“改首页—预览—发布—回滚”，不需要解释技术术语。

### 阶段 1：草稿与内容维护 MVP

- `Site`、`SiteEntry`、revision、导航和设置服务。
- 结构化编辑器、自动保存、冲突恢复、页面/文章/案例列表，以及三步案例创建向导。
- 素材原图上传、签名校验、去重、引用关系、安全预览、隔离派生图和焦点裁切均已完成。
- 从本地资料库选择内容创建站点草稿。

退出条件：重启后草稿和 revision 完整；并发修改不静默覆盖；素材引用可追踪。

### 阶段 2：确定性公开站点渲染

- 共享渲染器和基础主题。
- 首页、通用页、文章/案例列表与详情、404、SEO、站点地图和 RSS。
- 管理后台桌面/手机预览复用生产渲染器。
- HTML 安全、断链、无障碍和资源预算检查。

退出条件：同一发布清单在不同机器生成相同语义产物；无脚本注入和内部路径泄漏。

### 阶段 3：真实发布、域名与回滚

- 本地目录适配器先验证完整发布包、清单、检查和导出。
- Cloudflare Pages Direct Upload 作为首个真实静态发布适配器。
- 发布计划、确认绑定、不可变上传、远端验证和原子激活。
- 自定义域名所有权/解析状态引导。
- 发布历史、健康状态、不确定结果核对和一键回滚计划。
- 阿里云 OSS + CDN 已通过同一契约交付：连接验证、不可变上传、入口激活、CDN 刷新、线上核验、失败恢复和历史回滚均有自动测试。
- v0.20 扩展项：为 SSH 自托管增加独立 AliDNS 凭据、DNS-01 ACME、私网固定地址 HTTPS、证书原子部署、受控 Web 重载、续期预警与证书恢复；不改变内容发布的原子版本协议。

退出条件：发布失败不影响旧版；重复执行幂等；历史健康版本可在一次确认后恢复；完整导出包不依赖原云平台即可验证。

### 阶段 4：内容效率与运营

- 草稿定时发布和撤稿计划。
- AI 辅助标题、摘要、SEO 和替代文本，保持人工采纳与发布确认。
- 站点内容搜索、分类和标签。
- 无 Cookie 的基础访问统计或外部统计连接器。
- 导出、备份、恢复和素材生命周期管理。

### 阶段 5：扩展能力

- 多语言、多个站点和团队审核流。
- 联系表单及反垃圾、隐私和投递治理。
- 更多主题和发布适配器，包括专业视图中的自有主机。
- 内容 API、Webhook 和外部编辑器集成。

## 15. 首版验收场景

1. 新用户在 3 分钟内建立一个含首页、关于和联系方式的可编辑预览站点。
2. 已有可用全球云托管账号的用户在 10 分钟内把站点发布到临时地址；绑定自定义域名不计入首次成功门槛。
3. 用户在 2 分钟内修改联系方式、预览并发布，不需要打开帮助文档。
4. 用户修改首页标题，保存后线上内容不变；确认发布后线上才变化。
5. 两个窗口同时修改同一页面时，后提交者看到冲突与恢复选项，不覆盖先提交内容。
6. 用户上传超限、伪装类型或损坏图片时得到明确拒绝，其他草稿不受影响。
7. 用户删除一篇文章，发布前看到“这个页面将不能访问”以及受影响的站内链接，不先看到 URL 或状态码术语。
8. 构建或上传失败时旧站继续可用，后台显示可执行的下一步。
9. 发布请求超时后系统先核对远端结果，不重复生成公开版本。
10. 普通用户选择“恢复上一版”，预览影响后恢复，当前草稿仍保留。
11. 手机访客可阅读首页、文章和联系信息；后台 390 px 可完成编辑和发布确认。
12. 站点产物不包含控制平面 API、内部路径、凭据、草稿内容或未引用私有素材。
13. 新用户默认只看到普通视图，不接触专业术语也能完成首次发布和恢复上一版。
14. 用户在“我的设置”切换到全局专业视图后可访问高级 SEO、域名、发布和诊断；切回普通视图后配置保留且页面恢复简洁。
15. 专业用户从当前页面不超过两次操作即可打开该页面的高级设置，返回后保持原编辑位置。
16. 普通视图下打开专业深链接不会落入空白页或无权限假象，而是返回对应普通页面并给出切换方式。
17. 中国大陆托管条件未满足时，产品明确区分“内容已准备”和“网站可上线”，不会显示虚假成功。
18. 用户可以导出完整站点包；断开云平台不会自动删除线上网站或用户的本地内容。
19. 专业用户可以为自有服务器绑定内网域名并取得公开可信证书；系统不要求公网 A/AAAA，也不跳过 TLS 校验。
20. DNS、签发、证书上传或 Web 重载任一步失败时，旧证书和旧站点继续可用；证书私钥、AccessKey 和 TXT challenge 不进入状态、日志、审计正文或下载接口。

## 16. 开工前需要确定的产品输入

- 官网名称、主域名和品牌一句话介绍。

- 首批页面、服务、案例和文章内容清单。


规则：

- 顶部始终只保留“访问网站、预览、发布网站”三个站点动作。
- 无未发布修改时禁用“发布网站”并说明“网站已经是最新版本”。
- 发布异常优先说明旧网站是否仍正常，不用红色技术错误占据首页。
- 专业视图只增加“高级设置”入口，不在首页堆放构建编号和平台日志。

### 17.6 390 px 手机规则

- 网站首页保持状态、待发布修改和一个主操作“发布网站”；其他动作进入清晰的快捷操作列表。
- 编辑器一次只显示内容或预览，切换后保留输入焦点与滚动位置。
- 底部固定操作最多两个：“预览”“发布网站”。
- 发布确认使用全屏页面，不使用内容超长的底部抽屉。
- 所有卡片、列表和设置无横向滚动，44 px 以上触控目标，系统返回键不会丢失草稿。

## 18. 普通文案与状态规范

| 内部状态或概念 | 普通视图文案 | 主操作 |
| --- | --- | --- |
| no site | 还没有网站 | 创建我的网站 |
| draft only | 网站还没有发布 | 预览网站 |
| saved draft | 已自动保存 | 无需操作 |
| dirty against production | 有 {{count}} 项修改尚未发布 | 查看修改 / 发布网站 |
| building/uploading | 正在发布网站 | 查看进度 / 取消发布（可取消阶段） |
| verifying | 正在检查网站是否已经更新 | 等待检查 |
| active | 网站发布成功 | 访问网站 |
| failed, old active | 这次没有发布成功，原网站仍正常 | 查看解决方法 / 重试 |
| uncertain | 暂时不能确定是否发布成功，正在核对 | 等待核对 |
| domain pending | 网站地址还需要完成设置 | 继续设置 |
| filing pending | 内容已准备，完成网站备案后可以上线 | 查看备案步骤 |
| rollback available | 可以恢复到上一个正常版本 | 恢复上一版 |
| credential expired | 网站连接已失效，线上网站不受影响 | 重新连接 |

普通文案禁止把以下词作为主标题或主操作：Bucket、CDN、构建、部署流水线、Token、AccessKey、revision、manifest、fingerprint、atomic、rollback、canonical、JSON-LD。它们只在专业视图、平台原文或折叠技术详情中出现。
