## 1. 文档目的

本文定义 MyAgentTool 下一阶段如何把本地文档、远程文档、多维表格和其他业务数据与任务结合，同时不把“连接数据源、配置 API、调用 CLI、选择提供方”等技术工作暴露给普通用户。

本文先固定产品边界、用户流程、领域概念、权限模型和验收标准。以下事项完成评审前，不进入生产代码开发：

1. 普通用户原型及术语评审。
2. 资源范围、数据新鲜度和写入审批规则评审。
3. 飞书多维表格首个映射样例评审。
4. 安全、审计、失败恢复和撤销边界评审。
5. 服务端领域模型与现有本地资料库兼容性评审。

## 2. 背景与问题

现有本地资料库已经支持用户查找内容、将内容加入任务，并在运行时为 Codex 或 Claude 准备受控的本地文件。下一阶段需要覆盖更多数据形态：

- 本地或远程文档；
- 飞书多维表格、Airtable 等结构化表格；
- 项目共享的数据集和业务视图；
- 可作为交付目标的文档、表格或业务系统；
- 由 CLI 或 HTTP API 提供访问能力的数据源。

如果直接把“添加连接、授权账号、选择 API、运行 CLI、配置字段映射”交给普通用户，会产生三个问题：

1. 用户被迫理解技术接入，而不是完成任务。
2. 相同业务资料因提供方不同而表现成完全不同的产品流程。
3. AI 容易获得超出当前任务所需的数据和操作能力。

因此，产品主对象不能是“连接器”，而应是与当前任务有明确关系、已由系统治理的“任务资料包”。

## 3. 已确定的产品决策

### 3.1 普通用户看任务，不看连接

普通用户界面不得提供以下入口或概念：

- 连接数据源；
- 添加 API Key、Token 或账号凭据；
- 安装、选择或运行 CLI；
- 选择 MCP、HTTP、SDK 或命令行协议；
- 配置提供方字段、端点、命令、参数或权限范围；
- 浏览组织内所有已连接资源。

这些能力由管理员、项目负责人、应用安装流程或系统预配置承担。普通用户只看到已经允许用于当前项目或任务的业务资料。

### 3.2 任务资料包是统一入口

每个任务可以拥有一个“任务资料包”，用于说明 AI 和用户在本任务中：

- 必须读取哪些资料；
- 可以参考哪些资料；
- 可以查询哪些数据；
- 可以提出修改建议的对象；
- 可以使用哪些输出模板；
- 结果可以交付到哪里。

资料包只表达任务可见的业务能力，不暴露其背后的提供方和传输方式。

### 3.3 查询与操作严格分开

- 查询能力默认只读，并被限制在任务资料包声明的范围内。
- 普通写入先生成可审阅的变更草案，不直接提交。
- 用户批准后才能提交写入，并在提交前重新校验目标版本和权限。
- 删除、覆盖、大批量修改、对外发送等高风险动作必须单独强确认，不得被普通任务审批隐式放行。

### 3.4 CLI 和 API 是后台实现，不是产品分类

一个资源可以由本地文件、供应商 HTTP API、官方 CLI 或内部服务提供。产品层不根据访问方式拆分用户体验。

```text
普通用户 / AI 任务
        ↓
任务资料包能力
        ↓
统一资源领域服务与治理边界
        ↓
连接器适配层
        ↓
本地文件 / 供应商 API / 受控 CLI / 内部服务
```

受控 CLI 只能作为连接器适配器运行，不能把任意命令、参数、工作目录、环境变量或原始凭据暴露给 AI。

## 4. 产品目标与非目标

### 4.1 产品目标

1. 普通用户从任务出发即可理解本任务会使用什么资料和数据。
2. 文档、结构化数据和交付目标使用一致的选择、授权和审计语义。
3. Codex、Claude 或后续 Agent 使用相同的任务级资源合同。
4. AI 只能查询当前任务明确绑定的资源和范围。
5. 任何外部写入都可预览、可归因、可审批，并尽可能可恢复。
6. 本地资料库现有能力可以平滑纳入，而不是重建第二套内容系统。

### 4.2 非目标

首个版本不计划：

- 面向普通用户提供通用连接器市场或连接管理中心；
- 允许 AI 自行发现和绑定组织内的新数据源；
- 提供任意 SQL、任意 Shell 或任意供应商 API 调用；
- 默认把整个表格、知识库或网盘交给模型；
- 在没有预览和批准时直接修改远程数据；
- 用自然语言权限描述替代服务端强制授权；
- 为每个供应商设计一套独立的任务界面；
- 在本阶段同时支持所有表格和文档提供方。

## 5. 用户与职责边界

| 角色 | 主要职责 | 可见内容 | 不应承担 |
| --- | --- | --- | --- |
| 普通用户 | 创建和完成任务，选择已有业务资料，审核建议与变更 | 任务资料、可查询范围、来源业务名称、新鲜度、待确认变更、交付结果 | 连接器、凭据、CLI、API、字段协议配置 |
| 项目负责人 | 决定项目默认资料、任务模板和可用业务范围 | 项目资源目录、业务名称、用途、默认绑定和权限级别 | 日常处理底层协议错误 |
| 管理员 | 安装和维护连接器、授权账号、限定组织范围、处理健康问题 | 提供方、账号、权限、字段映射、同步与审计状态 | 代替普通用户决定某次业务变更是否正确 |
| 审核人 | 判断写入草案是否符合业务意图 | 变更前后值、影响范围、数据版本、依据和风险 | 查看或复制底层凭据 |
| AI 任务助手 | 在任务范围内读取、查询、形成建议和准备交付 | 任务级资源描述、受限查询工具、受控原文或行记录 | 扩大范围、绑定新连接、绕过审批或直接运行供应商 CLI |

同一用户可以拥有多个角色，但界面必须按照当前任务显示必要能力，不能因为用户同时是管理员就在普通任务页展示连接配置。

## 6. 普通用户心智模型

### 6.1 任务资料包

任务详情使用“任务资料”作为普通用户主标题，“任务资料包”可用于引导说明。资料按用途分组：

| 分组 | 用户理解 | 示例 |
| --- | --- | --- |
| 必须使用 | 没有它就不能可靠完成任务 | 客户询价邮件、产品清单、需求文档 |
| 可供参考 | 有助于判断，但缺失时任务仍可继续 | 历史报价、相似任务、规范说明 |
| 可查询数据 | AI 可在限定范围内按需查找 | 当前客户记录、有效价格表视图、库存表 |
| 待确认操作 | AI 可以准备变更，但需要人确认 | 新增跟进记录、更新任务状态、填写报价台账 |
| 输出样式 | 约束交付的结构和格式 | 报价模板、周报模板、字段规范 |
| 交付位置 | 批准后结果要保存或发送到的位置 | 项目文档目录、指定数据表、审批后的消息草稿 |

空分组不显示。普通任务不因为系统支持某类资源，就展示全部六个分组。

### 6.2 普通用户可见的资源信息

每项资源最多优先展示：

- 业务名称；
- 用途；
- 当前可用性；
- 数据范围，例如“华东区有效商品”或“本任务关联客户”；
- 新鲜度，例如“刚刚更新”或“数据截至 8 月 14 日 18:00”；
- 是否允许提出修改；
- 异常时唯一明确的恢复动作。

提供方名称只在有助于识别来源时作为次要说明，例如“客户台账 · 飞书”；不显示 Base ID、Table ID、路径、端点、命令名或访问令牌。

## 7. 核心用户流程

### 7.1 任务由模板自动获得资料

```text
用户创建“处理客户询价”任务
-> 系统根据项目和任务模板附加所需资料
-> 任务页显示询价原文、有效价格表、报价模板和台账交付目标
-> 用户检查范围并交给 AI
-> AI 在任务范围内读取和查询
-> AI 生成报价草稿与台账变更草案
-> 用户分别审核交付内容和台账变更
-> 系统提交已批准的结果并留下记录
```

这是首选路径。高频任务不应要求普通用户每次重新寻找相同数据。

### 7.2 用户为任务补充已有资料

```text
任务提示缺少必要资料
-> 用户选择“补充任务资料”
-> 只浏览当前项目允许使用的业务资料
-> 按业务名称搜索或选择
-> 系统说明加入后的用途和范围
-> 用户确认加入
```

选择器不提供“新建连接”。找不到所需资料时，用户只能“请求项目负责人补充”，并保留当前任务上下文。

### 7.3 AI 在运行中按需查询

```text
AI 读取任务资料摘要
-> 判断需要查询有效价格表
-> 使用任务级查询能力筛选相关产品
-> 只返回完成当前步骤所需的列和有界行数
-> 运行记录说明查询了哪个业务资料及其范围
-> AI 继续形成结果
```

普通用户不需要选择查询工具，也不需要看到查询协议。专业详情可以显示人类可理解的筛选条件，但不默认展示原始请求负载。

### 7.4 AI 提议修改结构化数据

```text
AI 根据任务结果形成变更草案
-> 系统校验字段、权限、目标记录和当前版本
-> 用户查看将新增、修改或清空的单元格
-> 用户批准或退回修改
-> 系统再次检查目标是否已变化
-> 未冲突时提交
-> 保存前后值、批准人、执行结果和可恢复信息
```

如果目标在预览后已变化，原批准失效，必须刷新草案后重新审核。

## 8. 资源领域模型

本节描述产品和服务端共享的概念边界，不在本需求阶段确定数据库表结构。

### 8.1 Resource

`Resource` 表示用户可以理解的业务资料或数据能力，而不是某个连接实例。

建议属性：

```text
Resource
  id
  ownerScope
  displayName
  description
  resourceKind
  capabilities
  sensitivity
  freshnessPolicy
  availability
  businessScope
```

首批 `resourceKind`：

- `document`：单个文档或逻辑文档；
- `document_collection`：受限文档集合；
- `structured_dataset`：表格、视图或记录集合；
- `output_template`：输出模板；
- `delivery_target`：受控交付位置。

一个资源可以同时具有读取和建议修改能力，但能力必须分别声明和授权。

### 8.2 TaskResourceBinding

`TaskResourceBinding` 表示资源为什么出现在某个任务里，以及本次任务允许怎样使用它。

```text
TaskResourceBinding
  id
  taskId
  resourceId
  purpose
  allowedCapabilities
  scopeConstraint
  required
  versionPolicy
  boundFrom
  boundBy
  boundAt
```

关键约束：

- 绑定只授予当前任务所需的最小能力；
- 项目有权使用某资源，不代表每个任务自动获得它；
- 绑定必须记录来源：项目默认、任务模板、用户选择或系统规则；
- 删除任务绑定不删除原始资源；
- 任务运行要记录实际使用的资源版本或查询时间点。

### 8.3 ResourceConnectorBinding

`ResourceConnectorBinding` 是管理侧对象，负责把业务资源映射到底层连接器。

```text
ResourceConnectorBinding
  resourceId
  connectorId
  providerObjectRef
  fieldMapping
  enforcedScope
  credentialRef
  health
```

该对象不得进入普通用户响应、AI 提示词或任务级工具描述。AI 只能看到 `Resource` 和 `TaskResourceBinding` 经过裁剪后的任务视图。

### 8.4 与本地资料库的关系

现有本地资料库的 `content record` 继续作为本地文档的权威内容身份。新模型通过资源映射复用它：

```text
本地 content record
        ↓ 映射为
document Resource
        ↓ 绑定为
TaskResourceBinding
```

不复制原文件，不重建索引，不改变现有任务内容引用和运行时物化边界。结构化远程数据不伪装成本地文件；只有任务确实需要固定快照时，才创建带来源和时间点的新快照对象。

## 9. 多维表格与结构化数据要求

### 9.1 首批支持范围

首个结构化数据试点建议选择飞书多维表格的只读视图，具体试点对象在细节评审中确定。首批能力限定为：

- 读取已配置视图的字段说明；
- 按允许字段筛选、排序和分页；
- 按稳定记录标识读取单条记录；
- 返回有限字段和有限记录数；
- 显示数据更新时间和截断状态；
- 对公式、人员、附件、关联记录等复杂字段返回规范化展示值和必要的类型说明。

首批不支持跨表任意联接、任意公式执行、任意脚本、下载全部附件或绕过视图范围。

### 9.2 数据范围

每个结构化资源必须绑定一个服务端强制范围，例如：

- 固定 Base、表和视图；
- 固定允许字段集合；
- 强制组织、区域、客户或项目过滤条件；
- 单次和单次运行的最大记录数；
- 可访问附件的类型与大小；
- 是否允许查看被隐藏或已归档记录。

AI 提交的筛选条件只能进一步缩小范围，不能覆盖强制条件。

### 9.3 新鲜度与一致性

资源必须声明一种版本策略：

| 策略 | 行为 | 适用场景 |
| --- | --- | --- |
| 运行时最新 | 每次查询读取当时可见数据，并记录查询时间 | 库存、状态查询 |
| 任务首次使用时固定 | 首次读取后固定版本或快照摘要 | 报价依据、审核材料 |
| 明确快照 | 只使用已发布或已归档版本 | 合同模板、财务周期数据 |

界面不能只显示“已同步”，必须说明数据时间点。若提供方无法给出稳定版本，应保存查询条件、返回记录标识、时间和内容摘要，以支持后续追溯。

### 9.4 字段语义

管理员负责把提供方字段映射为稳定业务字段。普通用户和 AI 使用业务字段名，不依赖可能变化的列 ID 或供应商类型名。

字段映射变更必须版本化。字段被删除、改名或类型变化时，资源进入“需要维护”，不能悄悄把空值当作真实业务值。

## 10. 能力与操作分级

| 级别 | 示例 | 默认处理 |
| --- | --- | --- |
| L0 查看描述 | 查看资源名称、用途、新鲜度 | 任务内自动允许 |
| L1 只读查询 | 搜索文档、筛选表格、读取记录 | 在任务范围和配额内自动允许，完整留痕 |
| L2 准备草案 | 生成新增行、字段更新、消息或文档草稿 | 可自动生成，但不得提交 |
| L3 可恢复写入 | 新增记录、更新指定字段、保存新文档版本 | 必须展示差异并由有权用户批准 |
| L4 高风险操作 | 删除、覆盖、大批量修改、对外发送、改变权限 | 独立强确认；首个版本原则上不开放 |

批准必须绑定：

- 当前任务和运行；
- 明确资源与目标记录；
- 预览时的数据版本；
- 精确字段和变更值；
- 操作数量和风险等级；
- 有效期与批准人。

批准一项变更不能转化为同类资源的长期写权限。

## 11. AI 任务级工具合同

Agent 侧工具应围绕任务资源命名，不围绕提供方命名。建议最小合同：

```text
task_resources.list
task_resources.search
task_resources.read
task_resources.query
task_resources.propose_change
```

后续经审批执行写入时，由 MyAgentTool 自己消费已批准草案；不要求 AI 获得通用的 `commit` 工具。

所有调用必须绑定：

- 当前活跃任务运行；
- 发起用户和所属团队；
- 当前项目和任务；
- 已绑定资源；
- 被允许的能力和强制范围；
- 单次调用及整次运行配额；
- 取消信号和审计上下文。

Agent 不得调用 `feishu.*`、`airtable.*` 或供应商 CLI。连接器适配层负责把任务级合同翻译为供应商调用，并规范化结果和错误。

## 12. 连接器运行要求

### 12.1 统一适配边界

无论底层使用 HTTP API、SDK 还是 CLI，连接器都必须满足同一领域合同：

- 输入输出结构化且有版本；
- 未声明字段拒绝处理；
- 凭据使用服务端引用和短期授权，不进入参数、日志或 AI 上下文；
- 支持超时、取消、速率限制和有界重试；
- 诊断输出与业务结果分离；
- 提供方错误转换为稳定的领域错误；
- 所有读写经过租户、项目、任务和资源范围校验。

### 12.2 CLI 适配器额外要求

- 只能调用预注册的可执行文件和固定子命令；
- 参数由结构化请求生成，不能拼接自然语言或任意 Shell；
- 工作目录和环境变量由运行时固定；
- 标准输出只承载结构化结果，标准错误只承载已脱敏诊断；
- 禁止向 AI 暴露命令路径、原始参数和环境；
- CLI 自带的本地登录状态也必须被当作凭据边界管理；
- CLI 升级后需通过合同测试才能恢复可用状态。

## 13. 页面与交互需求

### 13.1 任务详情

任务详情新增或收敛为“任务资料”区域：

- 默认显示本任务实际拥有的资料，不显示可连接的数据源；
- 优先展示必须使用、可供参考和可查询数据；
- 有写入草案时才显示“待确认操作”；
- 显示资料不可用、过期或范围变化，并给出一个恢复动作；
- 技术详情折叠放置，不干扰主任务流程；
- 390 px 宽度下仍能查看资源名称、状态和主要动作。

### 13.2 补充资料选择器

- 只显示当前项目已授权、允许普通用户自行加入的资源；
- 支持按业务名称、用途和内容类型搜索；
- 明确加入后是“必须使用”“可供参考”还是“可查询”；
- 不显示连接状态、提供方对象标识或字段映射；
- 无结果时提供“请求补充资料”，不提供“新建连接”。

### 13.3 变更审核

- 用业务语言显示目标和后果；
- 表格变更按新增行、修改字段、清空字段分组；
- 显示变更前值、变更后值和 AI 使用的依据；
- 明确影响记录数量；
- 冲突后禁止沿用旧批准；
- 部分成功时逐项显示结果，不用一个总成功掩盖失败项；
- 高风险操作与普通交付审核分开。

### 13.4 普通用户文案原则

推荐：

- “任务资料”
- “可查询数据”
- “资料由项目提供”
- “数据截至……”
- “AI 准备了 3 项变更，确认后才会更新”
- “目标内容已变化，请刷新后重新确认”
- “请求项目负责人补充资料”

避免：

- “连接数据源”
- “配置 Connector”
- “运行 feishu-cli”
- “调用 API”
- “MCP Server 不可用”
- “Base/Table/View ID”
- “Token 已过期”

底层凭据失效时，普通用户文案应为“这项资料暂时不可用，已通知负责人”，管理员再看到具体修复原因。

## 14. 失败与恢复

| 情况 | 普通用户行为 | 管理侧行为 |
| --- | --- | --- |
| 资料暂时不可用 | 看到是否阻塞任务，可重试或请求负责人处理 | 查看连接、凭据、配额和提供方诊断 |
| 必须资料缺失 | AI 不进入实质执行，提示补充资料 | 检查模板或资源授权 |
| 参考资料缺失 | 明确记录省略原因，任务可继续 | 可修复后重新运行 |
| 查询结果过多 | AI 缩小条件；不自动下载全部数据 | 调整资源设计而非临时放大无限配额 |
| 数据在审批后变化 | 原草案和批准失效，重新生成差异 | 查看并发冲突记录 |
| 部分写入成功 | 停止后续依赖操作，逐项展示成功和失败 | 使用幂等键恢复或补偿 |
| 任务被取消 | 中断查询和未提交操作；已提交结果保留 | 审计说明取消点和已产生影响 |
| 字段映射失效 | 资源标记为需要维护，不把缺失字段当空值 | 修复并发布新的映射版本 |

失败恢复不得要求普通用户复制错误码、运行 CLI 或重新授权外部账号。

## 15. 安全、隐私与审计

### 15.1 最小范围

- 资源授权、任务绑定和运行调用三层均要校验范围；
- 查询只允许缩小预配置范围；
- 返回字段、记录数、字符数、附件数和累计读取量均有上限；
- 任务结束或取消后，动态查询授权立即失效；
- 资源从任务移除后，后续调用不能继续读取。

### 15.2 不可信内容

远程文档、表格单元格、附件和历史 AI 输出均是不可信数据，不能成为系统指令、审批结果或权限声明。连接器返回内容必须保留不可信标记，Agent 适配器必须继续执行现有提示注入隔离规则。

### 15.3 审计记录

至少记录：

- 谁在何时把什么资源以何用途绑定到任务；
- 哪次运行查询了什么资源和业务范围；
- 返回了多少记录或内容量，是否截断；
- 哪个变更草案基于哪些任务证据形成；
- 谁查看并批准了什么精确差异；
- 实际提交结果、提供方版本、部分失败和恢复动作；
- 连接器健康变化，但不记录原始凭据和不必要的业务全文。

普通运行记录显示业务摘要；完整技术审计仅向有权角色开放。

## 16. 非功能要求

- 列表和搜索响应必须有界，支持稳定分页。
- 所有写入请求使用幂等键，重试不得重复新增记录或重复发送。
- 连接器暂时不可用不能破坏任务、已有资料绑定或本地原件。
- 同一任务在相同资源版本和查询条件下应具备可解释的复现证据。
- 新连接器不得增加普通任务首页的首屏复杂度。
- 连接器代码、领域服务和 Agent 适配器相互独立，供应商变化不应修改普通用户流程。
- 首个试点必须覆盖桌面、键盘和 390 px 移动布局。
- 查询和写入日志必须脱敏，不能在正常错误响应中包含凭据、绝对路径或完整远程负载。

具体性能、配额和保留期限在试点数据量确认后写入开发合同，不在本草案中猜测固定数字。

## 17. 分阶段范围

### 阶段 0：需求与原型打磨

目标：在写生产代码前消除用户流程和边界歧义。

- 用三个真实业务任务验证任务资料包分组；
- 完成普通用户任务详情、补充资料、运行中查询和变更审核低保真原型；
- 定义飞书多维表格试点的真实表、视图、字段和强制范围；
- 完成角色权限矩阵、失败矩阵和文案评审；
- 决定首批只读范围与后续写入的明确切割线；
- 评审本地资料库兼容和迁移路径。

退出条件：第 19 节的开发前决策全部关闭，并形成可测试原型。

### 阶段 1：统一任务资源模型

- 定义 `Resource`、`TaskResourceBinding` 及任务级能力合同；
- 把现有本地资料库引用映射为文档资源；
- 任务模板和项目默认资料可以产生绑定；
- Web 先只展示现有本地资源，验证信息架构不回退。

### 阶段 2：隐藏式连接器运行时

- 定义 API、CLI 共用的适配合同；
- 完成连接器身份、凭据引用、健康、取消、配额、审计和错误规范化；
- 仅提供管理侧配置和诊断，不增加普通用户连接入口。

### 阶段 3：飞书多维表格只读试点

- 映射一个经评审的只读业务视图；
- 支持有界字段说明、筛选、分页和单记录读取；
- 在任务资料中展示业务范围、新鲜度和可用性；
- 普通用户和 AI 均不能扩大预配置范围。

### 阶段 4：Claude/Codex 动态任务查询

- 注册提供方无关的 `task_resources.*` 只读工具；
- 端到端保留运行身份、用户身份、任务绑定和审计；
- 验证取消、超限、跨租户、跨项目、提示注入和提供方 parity；
- 文件物化仍是固定输入的首选路径，动态工具只解决运行中按需查询。

### 阶段 5：审批式写入

- 先支持 `propose_change`，再独立实现提交执行器；
- 只选择一种可恢复、低影响的新增或更新场景试点；
- 完成差异预览、版本冲突、批准失效、幂等和部分失败恢复；
- 删除、大批量覆盖和对外发送继续保留在范围外。

每个阶段必须独立可回退，不能以启用写入作为只读查询上线的前置条件。

## 18. 验收标准

### 18.1 普通用户体验

- 用户可以从任务详情说明“AI 会使用哪些资料、能查哪些数据、是否会修改外部内容”。
- 用户完成一次任务时不需要理解或操作连接器、API、CLI、MCP、账号令牌或提供方对象 ID。
- 任务模板自动提供常用资料；需要补充时只从项目已有业务资料中选择。
- 找不到资料时有明确的请求负责人路径，不出现新建连接入口。
- 只读查询不打断普通任务；任何外部写入在提交前都有业务差异预览。
- 390 px 页面仍能完成查看资料、补充资料、处理不可用状态和审核变更。

### 18.2 权限与安全

- AI 无法查询未绑定到当前任务的资源。
- 查询条件无法扩大管理员设置的强制范围。
- 任务取消、运行结束或资源解绑后，旧工具授权失效。
- 普通批准不能授权删除、批量覆盖、对外发送或后续任务写入。
- 提供方内容不能覆盖系统、任务、工具或审批规则。
- 普通用户响应、Agent 上下文和审计摘要均不泄漏凭据或连接器内部信息。

### 18.3 数据与恢复

- 每次查询可追溯到资源、业务范围、时间点和返回量。
- 截断、过期、部分数据和不可用状态不会伪装为完整结果。
- 预览后目标数据变化会使批准失效。
- 重试不会重复新增记录或重复交付。
- 部分成功可逐项识别并恢复，不会把整个操作错误显示为成功。
- 删除任务绑定不会删除本地原件或远程业务数据。

### 18.4 架构边界

- 本地文件、HTTP API 和 CLI 适配器共享任务级资源合同。
- Agent 工具不出现供应商专用命名或任意命令执行入口。
- 本地资料库继续使用现有内容身份、索引和受控物化链路。
- 连接器实现可以替换而不改变普通用户任务流程和 Agent 工具语义。

## 19. 开发前必须关闭的细节问题

以下问题必须形成明确结论、原型或合同测试，不能留给开发中临时决定：

### 19.1 业务试点

- 哪三个真实任务用于验证资料包分组？
- 首个飞书多维表格对应什么业务目标，而不是“演示查询表格”？
- 哪些资源由项目默认附加，哪些允许用户手动补充？
- 谁负责确认业务名称、字段含义和数据范围？

### 19.2 资源与版本

- 一个远程视图如何形成稳定的 `Resource` 身份？
- 视图改名、移动、删除或字段变化时怎样迁移？
- 哪些任务使用运行时最新数据，哪些必须固定快照？
- 附件、关联记录、公式和人员字段的首批精确行为是什么？

### 19.3 权限与审批

- 普通用户可自行绑定哪些项目资源？
- 谁能批准哪类写入，能否与任务发起人相同？
- 单条更新、批量更新和新增记录的风险阈值如何划分？
- 哪些写入能够可靠撤销，哪些只能提供补偿操作？

### 19.4 交互与文案

- “必须使用”和“可供参考”在任务页怎样最小化呈现？
- AI 动态查询应在时间线展示到什么粒度？
- 数据新鲜度、部分结果和范围限制如何用普通语言说明？
- 管理员和普通用户看到同一故障时各显示什么？

### 19.5 技术合同

- 任务级工具输入输出的精确 JSON Schema 和版本策略是什么？
- CLI 与 HTTP 适配器如何通过同一合同测试？
- 查询配额、分页游标、超时、取消和重试的具体值是什么？
- 写入预览如何绑定目标版本、字段映射版本和幂等键？
- 审计保留哪些摘要，哪些敏感正文禁止持久化？

## 20. 建议的需求打磨顺序

开发前按以下顺序评审，避免先讨论连接器技术而忽略用户任务：

1. **业务任务评审**：选定三个真实任务，列出输入、查询、操作和交付。
2. **普通用户原型评审**：验证任务页是否完全不需要“连接数据”的心智。
3. **资源与权限评审**：为每项资料确定范围、版本、新鲜度和最小能力。
4. **结构化数据样例评审**：用真实飞书字段走通筛选、截断、复杂字段和异常。
5. **变更与恢复评审**：演练并发冲突、重复提交、部分成功和取消。
6. **领域与适配合同评审**：最后确定模型、接口、CLI/API 适配和分期 Issue。

完成以上评审后，再将每一阶段拆成独立 Issue、验收夹具、风险说明和回退计划，开始开发。
