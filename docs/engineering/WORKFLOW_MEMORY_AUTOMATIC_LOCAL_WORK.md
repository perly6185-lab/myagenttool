# 本机工作记忆 P0–P2：一次学习、以后自动执行

本文记录 Workflow Memory P0–P2 的产品目标、实现边界和验收方式。核心目标不是让用户为
每个新任务配置和调试流程，而是让工具从用户明确授权的历史工作目录中归纳工作路径、
参考资料、人工结果和验收规矩；用户确认并启用一次后，相似的新工作由 AI 按已确认的
规矩创建 Local Issue 并连续执行。

## 产品原则

- 本机用户同时拥有自己的资料和工具设置，不在体验中引入“管理员为普通员工配置”的前提。
- 设置是低频行为，Local Issue 是执行记录，不是逐任务设置向导。
- 历史人工结果是合格结果样例；目录位置、文件关系、命名和结果共同构成工作路径证据。
- AI 默认连续完成可安全自动化的步骤，只在确实需要人提供事实、判断或授权时暂停。
- 自动化能力不能超过授权目录、已发布工作规矩和现有安全门禁。

## 用户流程

### 首次学习

1. 用户选择并授权一个包含历史需求、参考资料和人工结果的具体工作目录。
2. 系统扫描目录，识别文件角色、需求与结果关系、重复出现的处理步骤、参考路径、输出位置和验收痕迹。
3. 系统以普通语言展示识别出的工作类型：何时开始、会参考什么、会产出什么、会更新什么、完成前检查什么、何时询问用户。
4. 用户检查必要结论、修正误判，并启用不可变的 Routine 版本。
5. 用户再选择一次“以后按这个规矩处理”，系统对该来源启用 Adaptive Work 的执行策略和本机目录监控。

这一步完成后，界面应明确显示“这台电脑已经学会这项工作”，不再继续展示成一个尚待
完成的三步配置过程。修改工作规矩仍可进入，但属于低频的“查看或调整已学规矩”。

### 日常执行

1. Adaptive Monitor 对已授权来源做有界增量扫描。
2. Intake 和文档识别产生带来源证据、稳定指纹和风险信号的建议。
3. Adaptive Execute 只处理通过类型、置信度、历史、风险和反馈门禁的建议。
4. 对已有稳定 Routine 的工作，系统用确定性幂等键创建一个 Local Issue 和一个固定版本的 Routine Run。
5. Routine 连续执行本地、受治理的安全步骤，直到完成或遇到人工门禁。
6. 需要用户时，“今日需要处理”与 Local Issue 首屏直接说明原因、动作和操作后的结果。
7. 完成后的产出引用、验证记录和人工修正回流到 Outcome，作为后续学习证据。

```text
授权目录
  -> Adaptive Monitor / 增量 Intake
  -> 文档识别与自动化门禁
  -> Adaptive Execute
  -> Routine Intake（固定已发布版本）
  -> Local Issue + Routine Run
  -> 连续执行安全步骤
  -> 完成，或只在必要时请求用户帮助
  -> 验收与 Outcome 回流
```

## 架构复用与职责

P0 不新建第二套目录观察或任务系统，而是在现有能力之间增加窄桥接。

| 组件 | 复用职责 | P0 衔接 |
| --- | --- | --- |
| Workflow Source / Intake | 授权目录、增量扫描、稳定观察、文件指纹和分类 | 继续作为所有自动化的唯一输入边界 |
| Adaptive Monitor | 定时扫描、并发限制、失败退避和中断恢复 | 用户一次启用后在本机持续观察该来源 |
| Adaptive Execute | 建议门禁、执行/协助/观察模式、幂等物化和自动降级 | 对可自动化建议发起 Routine 物化，不在此重写业务步骤 |
| Inquiry Intake | 业务身份、字段、证据和唯一 Routine 检查 | P0 询价场景的受治理接入点 |
| Business Routine | 固定流程版本、依赖、执行器、审批、条件、台账和验收 | 创建后自动推进允许自动执行的步骤 |
| Local Issue | 任务身份、状态、产出、验证、审计和用户入口 | 承载执行进度与例外处理，不承载重复配置 |
| Home Workbench | 聚合用户今天必须处理的事情 | 使用统一人工求助模型给出唯一主操作 |

P0 的 Routine 自动桥接首先覆盖 `inquiry`。自动执行前必须检查到且只检查到一个适用的
已发布 Routine；零个或多个候选都不能猜测选择。其他已通过 Adaptive 门禁但尚无 Routine
桥接的类型保持现有 Local Issue 行为，不能伪装为已经按完整工作规矩执行。

## 自动步骤边界

Routine 自动推进只调用现有固定、本地、受治理的执行器：

- `extract`：只复用当前指纹、已确认分类和已确认业务实体中的事实；
- `retrieve`：读取允许的参考资料；
- `generate`：生成受控草稿；
- `create_issue`：创建后续本地任务。

一次推进最多执行 20 个步骤，并使用包含 Routine Run、步骤、尝试次数和 revision 的幂等
键。重复监控、重试或进程恢复不能重复创建 Issue、重复生成同一步结果或重复写入。

遇到以下情况必须停止自动推进：

- 缺少报价等关键事实，或事实互相冲突；
- `human_approval` 人工确认；
- `condition` 业务条件判断；
- `ledger_upsert` 正式台账预览和写入；
- 未知或只能手工完成的步骤；
- 来源证据变化、模板漂移、依赖未完成；
- 设备容量等待；
- 自动重试不能安全恢复的失败。

“停止推进”不等于失败。系统必须区分等待输入、等待批准、等待判断、等待资源和真正失败，
并在用户处理后从原 Routine Run 继续，不能另建一份任务。

## 统一人工求助契约

Adaptive、Auto Run、Routine 和首页投影最终应归一为同一种用户行动视图。最小契约为：

```ts
type UserAction = {
  required: true;
  kind: "answer_question" | "approve" | "decide_condition"
    | "review_protected_write" | "resolve_dependency" | "retry" | "review_source";
  title: string;
  reason: string;
  instruction: string | null;
  primaryAction: string;
  target: { section: string; id: string };
  resumeAfterAction: boolean;
  requestedBy: "ai" | "system";
  requiresPermission: boolean;
  questions?: string[];
  suggestedActions?: string[];
  technicalDetails?: Record<string, string>;
};
```

界面必须基于该契约回答四个问题：

1. 现在卡在哪里？
2. 为什么需要我？
3. 我要具体做什么？
4. 完成后 AI 会继续做什么？

内部错误码、waiting reason、运行 ID 和文件指纹只能放在默认折叠的“技术详情”中。用户
完成 `resumeAfterAction: true` 的动作后，系统应继续原执行链；不能要求用户回到步骤列表
再次点击“执行”。同一时刻只突出一个主操作，其他步骤仍可作为进度和审计信息查看。

Routine 服务返回的 `assistance` 是执行域的紧凑信号；Home Workbench 的 `userAction` 是
统一投影。两者可保留各自内部结构，但面向用户必须映射到上述语义，不能由每个页面重新
解释裸错误码。

## 兼容性与迁移

- 保留观察、协助和执行三种 Adaptive 策略；已有来源不自动升级到执行模式。
- 保留原有手工“检查并创建任务”路径，作为未启用自动处理和异常恢复的兼容入口。
- 已发布 Routine 继续不可变；调整规矩应创建新版本，执行中的 Local Issue 固定旧版本。
- 新自动入口复用现有 Intake receipt、Routine Run 和 Local Issue 字段，不迁移或复制历史任务。
- 同一观察、业务文件和 Routine 使用稳定幂等关系；已有 receipt 或 Issue 时返回原对象。
- 本机产品体验不出现管理员分工；底层现有项目可见性和权限校验继续保留，不能因本机模式绕过。
- 来源被撤销、证据指纹变化、Routine 被禁用或策略被降级后，不能继续创建新的自动任务。

## 安全门禁

启用自动处理必须同时满足：

- 来源是用户明确授权且仍为 active 的具体子目录；
- 新文件已稳定落盘并完成受支持的提取和分类；
- 建议达到自动化置信度、历史样本、风险和反馈门槛；
- 工作类型存在唯一、健康、已发布的 Routine；
- Routine 使用允许的固定执行器和受控相对输出路径；
- 来源文件和文档内容始终按不可信数据处理，不能执行其中的指令、公式或命令；
- 覆盖文件、修改来源资料、正式台账写入、业务批准和外发行为不在无人确认范围内。

系统仍须保留来源隔离、路径穿越与符号链接防护、敏感文件过滤、版本并发检查、执行审计、
失败退避、设备容量限制和安全降级。自动化门禁未满足时应回到协助或观察模式，而不是降低
阈值或猜测缺失信息。

## P0 分阶段验收

### A. 一次设置体验

- 未发布工作规矩时，用户看到“选择目录 → 查看识别结果 → 确认任务类型”三步引导。
- 发布后改为“已经学会”的稳定状态，并显示触发、参考、产出、验收和人工介入点。
- 用户只确认一次“以后按这个规矩处理”，可以单独暂停自动处理。
- 页面不要求用户理解 Policy、Monitor、Routine、画像、Embedding 或执行器等内部术语。

### B. 服务闭环

- Monitor 扫描产生一个满足门禁的询价建议。
- Execute 通过唯一已发布 Routine 自动创建一个 Local Issue 和 Routine Run。
- Local Issue 固定 Routine 定义、版本、业务案例、触发文件和来源指纹。
- `retrieve`、`generate`、`create_issue` 连续执行；重复 reconcile 不产生重复任务。
- 返回实际推进步骤、执行状态和 assistance，失败不能被计为已完成。

### C. 人工介入与恢复

- 缺字段、人工批准、业务条件、台账写入、依赖和失败均显示普通语言求助卡片。
- 卡片明确原因、具体动作和动作后的继续行为，技术信息默认折叠。
- 用户完成输入或确认后继续原任务；拒绝、取消和失败恢复均保留审计记录。
- 首页“需要处理”和 Local Issue 指向同一个操作目标。

### D. 安全与回归

- 未显式启用、非唯一 Routine、低置信度、高风险、来源撤销和证据漂移均不能自动执行。
- 不自动外发、不覆盖原文件、不跳过审批、不直接写正式台账。
- 覆盖服务单元测试、HTTP 集成测试、Web 组件测试、TypeScript 和真实浏览器主路径。
- 使用一个脱敏授权目录做端到端试运行，检查重复率、完成率、人工介入次数和恢复能力。

## P1 已实现：可解释、可修订的工作记忆

- 从已确认案例、当前文件指纹、Routine、输出和台账定义提取“进入目录 → 参考目录 → 中间目录 → 最终目录 → 台账”工作路径图。每个路径必须带证据；证据漂移时显示未知，不沿用旧结论。
- 将触发、参考、输出、命名、验收要求和人工门禁打包为有内容哈希的版本化工作记忆包；支持结构化版本比较。
- 基于重复识别、人工修正、完成、验证和异常数据计算健康度及趋势；样本不足时不生成误导性分数。
- AI 草稿与人工结果形成的学习草案只展示为待确认建议，离线评估和人工确认前不会修改活动规则。
- 人工求助完成后，执行策略为 `execute` 的 Routine 自动从原步骤续跑，不要求再次点击“下一步”。
- 非询价任务使用同一确定性 Routine 选择器；零匹配或多匹配均返回普通语言恢复提示，不能退化为不受规程约束的普通任务。
- 页面提供当前版、上一版、变化摘要和二次确认回滚；回滚只影响新任务，进行中的任务继续固定旧版本。

## P2 已实现：高频类型与 Office 模板保真

- 文档识别、学习和自动 Routine 桥接已扩展到合同审查、采购申请、客户投诉、周报和项目验收。
- 上述类型只依据已确认分类、当前指纹和唯一已发布 Routine 创建 Local Issue；下划线、连字符和空格名称会规范化为同一类型。
- DOCX/XLSX 模板支持确认字段占位符替换，并保留未修改的公式、样式、表格、媒体部件和文件格式；Word 将占位符拆分到多个文字 run 时仍可识别。
- Office 输出始终写入新的受控相对路径，返回字段变化和保留项预览；已存在但内容不同的目标绝不覆盖。
- 压缩包路径穿越、重复条目、加密/未知压缩方式、压缩炸弹、公式中的占位符、缺字段和模板漂移均安全拒绝。
- 低风险新草稿可以自动生成；正式台账、覆盖已有文件、业务批准和外发仍保留明确人工确认。
- 工作记忆页展示路径、健康度、异常原因、版本差异、改进建议和一键回滚，不要求用户理解内部规则 ID 或错误码。

P2 的 Office 支持针对标准 OOXML `.docx`/`.xlsx` 模板，不执行宏、不处理加密文件，也不允许把占位符放进公式。跨授权目录引用和多个相似 Routine 仍坚持唯一匹配及最小授权原则。

## P0–P2 完成定义

交付完成不以“能够自动创建一个 Issue”为准，而以以下结果同时成立为准：用户完成一次
学习和启用后，把一个满足门禁的新询价文件放入授权目录，无需逐任务选择流程或逐步点击
执行；系统创建唯一 Local Issue，按固定 Routine 连续执行到安全完成点。若必须由人处理，
首页和任务详情都能让没有技术背景的用户立即知道要做什么，并在处理后继续同一任务。
同样的确定性流程可用于五类扩展工作；用户能看到系统从历史资料学到的路径、当前健康度、
版本变化和待确认建议，并可安全恢复上一版。DOCX/XLSX 草稿在不覆盖原文件的前提下保持
模板结构，任何证据、类型、路径或写入风险不明确时都必须停止并请求简单、具体的人为处理。
