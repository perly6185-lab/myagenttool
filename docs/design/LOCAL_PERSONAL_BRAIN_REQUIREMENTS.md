## 1. 文档目的

本文定义“我的资料”如何从本机内容索引升级为普通用户可以持续使用的个人知识与行动入口。

目标不是复制一款云笔记产品，也不是让用户维护一个越来越复杂的资料库，而是利用 MyAgentTool 已有的本地原件、任务、AI 执行、交付文件、主机和网站发布能力，形成以下闭环：

```text
用户说明想完成什么
  -> 选择或添加有关资料
  -> AI 读取、理解并提出可执行结果
  -> 用户核验来源与执行范围
  -> 得到答案、成果、任务或操作结果
  -> 结果作为新资料继续积累
```

本文先固定产品定位、普通用户流程、信息架构、安全边界、阶段范围和验收标准。原型、检索评测和安全评审完成前，不直接实现主动记忆、语义搜索或外部 MCP 写入。

## 2. 产品定位

### 2.1 一句话定位

“我的资料”是一个让用户拿自己的资料直接问、直接做、继续推进工作的 AI 入口。

“本地优先、来源可追溯”是可信基础，不是首页卖点；“能完成什么”才是普通用户首先需要理解的价值。

### 2.2 与现有能力的边界

| 产品对象 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 我的资料 | 收集、索引、查找、提问、整理、回顾个人资料 | 不直接执行高风险外部操作 |
| 任务资料 | 固定某次任务必须或可以使用的资料范围 | 不承担个人资料的长期整理 |
| 任务运行 | 在受控范围内让 Codex、Claude 或其他助手执行 | 不默认读取整个资料库 |
| 我的成果 | 保存用户确认保留的输出及版本 | 不覆盖生成成果所依据的原件 |

“我的资料”发生在任务之前和任务之间；“任务资料”发生在一次明确执行之内。用户从回答创建任务时，只把所选引用和必要范围带入任务，不把整个资料库授权给 AI。

### 2.3 Channel、资料与任务的关系

Channel 是接收用户表达、文件和链接以及回传进展的入口，不是长期资料库，也不是另一套任务执行器。

```text
Channel 消息
  ├─ 保存、收纳 -> 我的资料
  ├─ 提问、总结、比较 -> 资料工作会话 -> Channel 回答
  ├─ 持续推进 -> 任务草稿 -> 用户确认 -> 任务
  └─ 修改主机、站点或外部状态 -> 操作预案 -> 用户确认 -> 受控任务

任务结果 -> Channel 回传
任务成果 -> 用户确认保存 -> 我的资料
```

固定边界：

1. 单纯保存消息、链接或附件只创建资料记录和收纳进度，不创建工作事项，也不占用任务队列。
2. 普通咨询和资料分析可以创建只读 AI 运行，但不创建任务、不修改原件。
3. “加入当前任务”只给用户选中的当前任务增加明确资料引用，不改变任务目标或执行顺序。
4. “创建新任务”先展示目标、所带资料和预计结果，确认后才创建工作事项。
5. Channel 身份只继承绑定用户已有的资料可见性；会话不能授权读取整个 Channel 历史或整个资料库。
6. 任务状态和结果可以回传原 Channel；普通回传消息不自动进入资料库。
7. 历史版本曾为“资料收纳”创建的任务可以保留用于审计，但新收纳和重启恢复不得继续补建此类任务。

用户无需选择内部对象类型。系统根据表达使用以下默认路由：

| 用户表达 | 默认结果 | 不会发生什么 |
| --- | --- | --- |
| “保存这个”“收一下” | 保存到“我的资料” | 不创建任务 |
| “看看这个”“总结一下” | 只读分析并在 Channel 回答 | 不修改资料或当前任务 |
| “加入当前任务” | 预览并添加资料引用 | 不创建后续任务 |
| “根据这些资料继续处理” | 形成任务草稿 | 未确认不执行 |
| “发布、上传、修改、删除” | 形成操作预案并进入受控任务 | 不在 Channel 对话中直接执行 |
| “进度怎么样” | 查询并回传现有任务状态 | 不创建新任务 |

### 2.4 差异化原则

1. 本机原件继续权威，索引和 AI 派生内容可重建。
2. 每个资料型回答都能说明依据，不能只给无法核验的结论。
3. 从资料到任务、文件或网站成果应比通用笔记产品更短。
4. 主动能力必须可解释、可关闭，并且不能偷偷扩大读取范围。
5. 云同步、团队知识广场和内容订阅不是首批竞争方向。

### 2.5 核心设计原则：先问目的，再谈资料

产品设计和开发排序必须围绕以下问题展开：

> 用户想拿这些资料完成什么？AI 能把它推进到哪一步？

因此，资料类型、目录、专题、索引、OCR 和语义检索都是后台支撑，不是用户主线。用户主线固定为：

```text
表达目的 -> 确认资料 -> AI 处理 -> 核验依据 -> 保存结果或继续行动
```

首页和资料卡不得要求用户先理解资料管理方法。用户既可以先说目的再选资料，也可以先选资料再选择“问问、总结、比较、整理、接着处理”。两条路径最终进入同一个工作会话。

## 3. 当前基线与问题

现有实现已经具备：

- 文章、邮件、任务、任务输入和任务输出的统一内容身份；
- 本地 FTS 和元数据筛选；
- 安全预览、原件定位、缺失/变化检测和索引恢复；
- 资料到任务的引用，以及运行时受控物化；
- 有界目录、摘要搜索和原文读取合同；
- 租户、项目、路径、配额、审计和不可信内容边界。

普通用户仍会遇到五个断点：

1. 首屏主动作是“刷新索引”，不是“添加资料”或“问资料”。
2. 新资料主要来自既有文章、邮件和任务流程，缺少统一收纳入口。
3. 搜索需要用户知道关键词，无法直接用问题表达目的。
4. 使用资料必须先选择任务，简单理解和比较也被迫进入任务流程。
5. 资料积累后没有专题、保存视图、时间回顾或可控的主动提醒。

## 4. 产品目标与非目标

### 4.1 产品目标

1. 新用户能在首屏理解“添加、提问、行动”三个核心能力。
2. 用户能添加文件、文件夹、文字、图片或链接，并明确原件保存方式。
3. 用户能对全部资料、一个专题或明确选中的资料提问。
4. 回答包含可打开的来源引用，并区分原文事实与 AI 推断。
5. 用户能从回答创建任务、保存成果或继续整理资料。
6. 关键词搜索始终离线可用；语义能力是可关闭的增强层。
7. AI 不能默认读取未选范围，也不能修改权威原件。
8. 所有能力在桌面、键盘和 390 px 移动布局下有可完成路径。

### 4.2 首批非目标

- 不做公共知识广场、内容市场或社交关注流；
- 不做默认云端全量同步；
- 不让 AI 自动读取整个磁盘或未注册目录；
- 不用向量检索替代确定性关键词搜索；
- 不在回答过程中直接覆盖、删除或移动原件；
- 不建立不可查看、不可编辑、不可关闭的“AI 人格档案”；
- 不同时实现语音录制、会议转写、团队共建和所有外部连接器；
- 不把 MCP、Embedding、RAG、索引版本等术语暴露给普通用户。

## 5. 用户目的与 AI 能完成的工作

### 5.1 用户目的分类

用户不需要先判断应该使用搜索、问答、任务还是自动化。产品先识别用户想得到的结果，再调用后台能力。

| 用户目的 | 用户会怎么说 | AI 的首要结果 | 推荐下一步 |
| --- | --- | --- | --- |
| 找答案 | “合同什么时候到期？” | 带原文位置的直接答案 | 打开原文、继续追问 |
| 看明白 | “帮我看懂这份报告” | 摘要、重点和术语解释 | 保存摘要、整理清单 |
| 提取信息 | “把联系人和报价列出来” | 结构化清单或表格 | 导出、补充到任务 |
| 比较判断 | “这两个方案差别是什么？” | 对比、冲突和缺失项 | 形成建议、创建决策任务 |
| 生成内容 | “整理成一篇文章” | 可编辑的草稿 | 保存结果、继续修改、发布 |
| 安排工作 | “根据会议记录安排下一步” | 负责人、事项和截止信息草案 | 确认后创建任务 |
| 执行操作 | “把这个版本发到我的站点” | 操作预案、目标和影响范围 | 确认后进入受控执行 |
| 回顾积累 | “我这周做了什么？” | 带来源的阶段回顾 | 补充遗漏、形成复盘 |

这八类是产品意图，不是需要用户选择的固定菜单。系统可以根据问题和资料给出建议，但用户始终可以用自然语言修改目标。

### 5.2 资料到结果的典型映射

| 资料 | 默认建议，不自动执行 | 用户可以得到什么 |
| --- | --- | --- |
| 会议记录、聊天记录 | 提炼结论、待办和责任人 | 纪要、任务清单、跟进邮件 |
| 合同、制度、报价 | 找关键条款、差异和风险 | 风险清单、版本对比、确认事项 |
| 文章、网页、个人笔记 | 总结、聚类观点、发现矛盾 | 选题、提纲、文章草稿 |
| 表格、报表、账单 | 提取数字、比较变化、标记异常 | 分析摘要、图表需求、核对清单 |
| 产品文档、需求、代码说明 | 回答问题、补齐测试场景 | 测试清单、Issue 草稿、开发任务 |
| 主机日志、配置文件 | 诊断原因、生成只读检查步骤 | 故障判断、修复预案、受控命令任务 |
| 图片、扫描 PDF | 识别文字和版面、归纳信息 | 可搜索内容、字段清单、内容草稿 |
| 历史任务与成果 | 复盘过程、比较版本、发现未完成项 | 复盘、下一步计划、可复用模板 |

首批原型必须至少使用四组脱敏夹具：客户邮件与附件、文章与个人笔记、会议记录、任务输入与结果。主机日志作为“转受控任务”的安全验证夹具，不在资料问答中直接执行命令。

### 5.3 AI 能力阶梯

| 层级 | AI 能力 | 默认行为 | 是否需要确认 |
| --- | --- | --- | --- |
| L1 读取 | 搜索、预览、定位、识别相关资料 | 只读明确范围 | 提问前持续显示范围即可 |
| L2 理解 | 总结、提取、解释、比较、判断资料是否充分 | 生成带来源的临时结果 | 不修改数据，无需逐次确认 |
| L3 产出 | 生成文章、报告、表格、清单或方案草稿 | 先预览，用户决定是否保存 | 保存为长期结果时确认一次 |
| L4 推进 | 创建任务、添加资料、生成发布或主机操作预案 | 展示将带入的资料和目标 | 创建或变更业务对象前确认 |
| L5 执行 | 修改文件、运行命令、上传、发布、发送或删除 | 必须转入现有受控执行流程 | 展示目标、命令/变更和影响后明确确认 |

“我的资料”内直接完成 L1-L3，L4 负责把用户目的和已确认资料转成任务，L5 复用任务、我的主机、我的站点已有审批与审计能力。不得为了体验顺滑而绕过执行确认。

## 6. 普通用户信息架构

### 6.1 一级页面

```text
我的资料
├─ 我想做什么（首屏输入）
├─ 常用动作（总结、比较、提取、整理成内容）
├─ 最近使用
├─ 专题
├─ 全部资料
└─ 回顾（有内容时出现）
```

“专题”是面向用户的逻辑分组，内部可继续使用 `KnowledgeCollection`。类型、项目、来源、时间、文件是否可用和处理状态继续存在，但不与核心动作竞争。索引和解析细节仅出现在故障恢复中。

### 6.2 桌面首屏草图

```text
我的资料                                             + 添加资料
用自己的资料找答案、整理内容或推进工作

[ 你想用这些资料做什么？例如：比较两份方案的差异       ] [开始]
  从：全部资料                                                [更改]

常用动作
[帮我总结] [对比分析] [提取信息] [整理成内容] [安排下一步]

最近使用                         专题
客户反馈                         网站内容
项目复盘                         产品研究

全部资料
[搜索资料] [类型] [项目] [更多筛选]
```

默认选中“全部资料”时只显示一句“从全部资料中查找”；用户点击“更改”才进入范围选择。首页不展示资料总数、索引数量、根目录、解析器或健康统计。

### 6.3 资料卡与批量选择

未选择时，资料卡只保留：

- `打开`：安全预览或定位原件；
- `问问这份资料`：直接进入工作会话；
- `接着处理`：显示总结、提取、比较、整理成内容等动作；
- 更多菜单：加入专题、查看详情、从列表移除。

用户选择两份及以上资料时，页面底部出现单一批量动作条：

```text
已选 3 份资料   [问问这些资料] [对比分析] [接着处理] [取消]
```

“刷新资料状态”“重新识别”“定位所在文件夹”等恢复动作不得占用卡片主操作位置。

### 6.4 工作会话页面

```text
< 返回我的资料            比较两份报价方案                    ···
正在参考：报价 A、报价 B                                      [更改]

你：比较价格、交付时间和售后条款

AI：
结论摘要…… [1][2]

主要差异
| 项目 | 报价 A | 报价 B | 依据 |
...

需要你判断
- 报价 B 没有说明……

[继续问] [保存这份结果] [创建任务]

[ 输入补充要求，例如：更重视交付时间                    ] [发送]
```

会话顶部始终显示当前参考范围。来源编号可打开安全预览并定位片段。候选数、召回方式、模型名和字符预算放在折叠技术详情中。

### 6.5 390 px 移动首屏

移动端只保留：

1. “你想用这些资料做什么”输入框；
2. “添加资料”和最多四个常用动作；
3. 最近使用和专题横向列表；
4. 全部资料列表；
5. 范围、筛选和更多动作进入底部抽屉。

回答页底部固定一个“继续问”输入框；保存、创建任务等后续动作放在回答末尾，不同时固定多个按钮。

## 7. 核心用户流程

### 7.1 先说目的，再找资料

```text
打开“我的资料”
-> 输入“根据最近客户反馈安排下一步”
-> 系统给出可能相关的资料，并说明为什么被选中
-> 用户增删资料或直接开始
-> AI 读取确认范围并生成结论与待办草案
-> 用户核验依据
-> 确认后创建任务
```

如果系统无法可靠确定资料范围，必须先展示候选供用户确认，不能默默扩大到整个资料库。若用户已明确选择专题或资料，则不再增加一次确认弹窗。

### 7.2 先选资料，再决定怎么用

```text
打开一份或选择多份资料
-> 选择“问问这份资料”或“接着处理”
-> 系统根据资料类型展示常用动作
-> 用户选择动作或直接输入要求
-> AI 给出带来源结果
-> 用户继续修改、保存或转成任务
```

常用动作只是自然语言模板。例如“对比分析”会预填“比较这些资料的主要差异、共同点和缺失信息”，用户可在开始前修改。

### 7.3 添加资料并立即使用

```text
选择“添加资料”
-> 选择文件/文件夹、粘贴文字、图片或链接
-> 系统用普通语言说明资料是否留在原位置
-> 添加完成后询问“接下来想用它做什么？”
-> 显示适合该资料的 3 个建议动作
-> 用户开始处理或返回列表
```

| 输入 | 默认权威原件 | 用户可见说明 |
| --- | --- | --- |
| 已存在文件/文件夹 | 原位置文件 | “文件仍在原位置，我们只读取你选择的内容” |
| 粘贴文字 | 应用管理的本地原件 | “已保存为可以导出的本地资料” |
| 截图/图片 | 应用管理的图片原件 | “已保留原图，识别结果出错时可以重新处理” |
| 公开链接 | 现有文章导入产物 | “已保存正文和原链接” |
| 音频/视频 | 后续阶段的应用管理原件 | “已保留原文件，转写内容可以重新生成” |

首批仅开放现有已索引资料问答；统一添加入口在基本闭环通过后开放，避免同时引入收纳与生成两套风险。

### 7.4 AI 生成结果

所有结果使用相同的五段结构，允许无内容的段落省略：

1. `直接结果`：先回答用户目的，不先复述处理过程；
2. `关键发现`：列出重点、差异、风险或提取字段；
3. `需要你判断`：显示资料冲突、缺失信息和 AI 推断；
4. `来源`：列出实际读取的资料和可打开片段；
5. `下一步`：继续问、保存结果、创建任务或准备执行。

回答状态必须覆盖：生成中、已完成、用户取消、资料不足、资料冲突、来源变化、来源无法读取、模型不可用和超出读取范围。模型不可用时，保留关键词搜索、预览和创建普通任务。

### 7.5 从结果到任务、主机或站点

```text
查看 AI 结果
-> 选择“创建任务”或具体后续动作
-> 系统展示任务目标、要带入的资料和预计产物
-> 用户确认
-> 创建任务并固定引用版本
-> 需要操作主机/站点时进入对应受控流程
-> 执行结果回到任务，并可由用户保存到“我的资料”
```

资料会话不能直接运行 SSH、SFTP、发布或删除。它只能生成操作预案并转入现有能力。确认页至少说明：操作对象、预计变更、所需权限、可否回退以及哪些资料将提供给执行 AI。

### 7.6 保存结果与版本

“保存这份结果”默认创建独立结果，不覆盖任何原件。保存对象记录：用户目的、生成内容、所依据资料、来源指纹、生成时间和后续修改版本。

用户可选择：

- 保存为普通结果；
- 整理成文章草稿；
- 导出为 Markdown，后续再扩展 Office 格式；
- 创建任务继续完善；
- 发送到“我的站点”的草稿区，仍需发布确认。

重复保存同一次会话生成新版本，不复制输入原件。自动生成的临时回答在用户明确保存前不进入资料索引，防止循环引用和资料污染。

### 7.7 专题与回顾

专题是逻辑分组，不复制或移动原件。用户可以新建、重命名、归档专题，把一份资料加入多个专题，并将当前搜索保存为常用视图。AI 可以建议归类，但批量改变必须确认。

回顾默认由用户主动打开，只包含可验证信息：本周新增和反复使用的资料、未完成任务、已形成结果，以及有明确来源的重复、冲突或待跟进线索。通知需要单独开启，并允许查看原因、关闭某类建议和清除历史。

问答会话、引用和回顾可以删除，不影响资料原件。专题删除只删除成员关系，不删除资料。任何“同时删除资料”的动作必须单独列出原件范围并再次确认。

### 8.1 会话状态机

```text
draft
  -> running
     -> completed
     -> awaiting_user -> running
     -> failed -> running
     -> cancelled
```

- `draft`：用户仍可修改目标和资料范围；
- `running`：范围已固定，正在检索或生成；
- `awaiting_user`：资料冲突、范围过大或执行目标不明确，需要用户选择；
- `completed`：本轮结果完成，但会话可继续追问；
- `failed`：保留已找到资料和可恢复原因；
- `cancelled`：立即终止模型请求和后续读取，不自动重试。

每次继续追问创建新消息和新引用集合。会话范围发生改变时创建新的 `retrievalRevision`，旧回答继续保留原范围和来源。

### 8.2 最小 API 设计

现有 `/api/local-content` 搜索、预览、健康检查和受控读取接口继续复用。新增接口按用户工作会话组织：

```text
POST /api/material-work-sessions
GET  /api/material-work-sessions/:sessionId
POST /api/material-work-sessions/:sessionId/messages
POST /api/material-work-sessions/:sessionId/cancel
GET  /api/material-work-sessions/:sessionId/events
POST /api/material-work-sessions/:sessionId/action-proposals
POST /api/material-work-sessions/:sessionId/action-proposals/:proposalId/confirm
POST /api/material-work-sessions/:sessionId/outcomes
```

首个 `POST` 接收 `userGoal`、显式范围和可选动作模板；不接收任意绝对路径。发送消息时服务端为本轮固定可见内容身份和读取预算。事件接口只发送阶段、增量结果和引用，不发送内部提示词或未授权候选。

M1 只实现会话、消息、引用和 `create_task` 提案；保存结果、站点草稿和主机操作提案按后续里程碑增加。所有写入接口使用幂等键、所有确认接口校验会话修订和资料指纹。

## 9. 检索与回答合同

### 9.1 两阶段检索

1. 现有 FTS、元数据和范围过滤形成有界候选集。
2. 可选的语义模型只在候选集上重排，或在评测通过后补充少量候选。

FTS 永远保留为离线回退。关闭模型、网络不可用或向量索引损坏时，关键词搜索仍然可用。

### 9.2 引用要求

- 每个来源引用绑定 `contentId`、读取时指纹和有界原文位置；
- 点击引用打开安全预览并定位到对应片段；
- 原件在回答后发生变化时，回答显示“来源已变化”；
- 多来源冲突不能被合并成没有分歧的单一结论；
- OCR、转写和 AI 摘要必须标记为派生内容，并能返回原件；
- 普通回答不显示绝对路径、根目录 ID、哈希或检索内部得分。

### 9.3 范围与配额

- 用户从资料或专题进入时，默认范围为当前明确选择的资料；从首页直接输入时默认为“全部可见资料”，并持续显示；
- “全部资料”需要在提问框附近持续显示；
- 单次候选数、读取文件数、单文件字符数和累计字符数均有上限；
- 跨项目和敏感邮件遵循现有可见性策略；
- 取消提问后，读取授权和模型请求都必须终止；
- 问答产生的临时内容不进入资料索引。

### 9.4 意图识别与动作模板

意图识别只决定界面结构和输出格式，不扩大权限。服务端保存用户原话，并允许一个会话同时具有主意图和辅助意图，例如“比较两份方案并整理成汇报”是 `compare + create`。

首批动作模板：

| 模板 | 输出合同 | 特殊检查 |
| --- | --- | --- |
| 直接回答 | 简短答案、依据、缺失信息 | 关键结论必须有引用 |
| 帮我总结 | 摘要、关键点、待确认项 | 不添加资料外事实 |
| 提取信息 | 用户字段或系统建议字段、缺失字段 | 保留原值和来源位置 |
| 对比分析 | 比较维度、各资料值、共同点、差异、冲突 | 不把未提及误写为“没有” |
| 整理成内容 | 目标受众、结构、草稿、来源 | 事实与创作性表达分离 |
| 安排下一步 | 待办、建议负责人、截止依据、依赖 | 负责人和日期无依据时标为建议 |

模板不是六套互不兼容的 Prompt。它们共享范围、候选、读取、引用和安全合同，仅输出结构不同。用户修改模板文案后，以用户原话为准。

### 9.5 生成编排

```text
规范化用户目的
-> 固定本轮可读范围
-> 关键词与元数据检索候选
-> 需要时请求用户确认候选
-> 按预算读取原文
-> 生成结构化结果和逐条引用
-> 服务端校验引用身份、范围和原件状态
-> 展示结果
-> 可选生成 ActionProposal
```

服务端校验至少包括：引用只能指向本轮实际读取内容；引用片段不能超出已读范围；来源发生变化时不能继续标记为“已核验”；操作提案只能携带用户已确认的引用；模型返回的路径、命令和外部链接一律视为不可信文本。

### 9.6 依据不足与模型降级

- 没找到资料：显示“暂时没在你的资料中找到答案”，允许更换范围、换种说法或添加资料；
- 找到但读不了：列出受影响资料和恢复动作，不生成伪结论；
- 多份资料冲突：并列展示观点和各自来源，不替用户隐藏冲突；
- 读取预算不足：先回答可支持部分，再建议缩小范围；
- 模型不可用：退回普通搜索和预览，可创建不含 AI 结果的任务；
- 用户要求外部知识：明确提示将离开“只根据我的资料”，并转成单独的研究任务。

## 10. 普通用户交互与文案

推荐主动作：

- “你想用这些资料做什么？”
- “问问这些资料”
- “帮我总结”
- “对比分析”
- “提取信息”
- “整理成内容”
- “安排下一步”
- “添加资料”
- “加入专题”
- “接着处理”
- “保存这份结果”
- “查看原文”

降级为次要或技术详情：

- “重新检查资料”，只在异常时出现；
- “暂时只能搜索标题”或“暂时无法读取正文”，技术详情再显示解析或索引状态；
- “原件仍在原位置”，替代存储模式解释；
- “来源已变化”，技术详情再显示指纹和版本。

普通用户状态表达：

| 内部状态 | 用户看到的内容 |
| --- | --- |
| direct support | 这条结论来自资料，并提供“查看原文” |
| inference | 这是根据资料做出的判断 |
| conflict | 这些资料的说法不一致 |
| insufficient | 现有资料不足以回答 |
| metadata_only | 暂时只能搜索标题和基本信息 |
| original unavailable | 原文件现在无法访问 |
| action proposal | AI 已准备好下一步，确认后才会执行 |

不向普通用户展示：

- FTS、Embedding、RAG、Chunk、向量得分；
- Root ID、绝对路径、内容哈希；
- MCP、provider adapter、检索合同版本；
- 模型原始提示词、内部候选和未授权资料标题。

## 11. 安全、隐私与治理

1. 新目录只能由用户显式选择或由现有业务流程注册。
2. 文件引用和应用管理副本必须在确认时明确区分。
3. 原件、提取文本、索引、AI 回答和执行副本使用不同生命周期。
4. 图片、邮件、网页、OCR、转写和历史 AI 输出始终是不可信内容。
5. 问答只读；修改、移动、删除、分享和发布继续走现有审批边界。
6. 回答审计记录范围、模型、读取量和引用身份，不保存不必要的完整正文。
7. 语义索引必须支持删除、重建、模型版本迁移和完全关闭。
8. 主动建议不默认读取新的范围，也不能变成绕过任务授权的后台 Agent。
9. 用户可以导出应用管理的个人笔记、专题成员关系和保存结果。
10. 删除专题、问答历史、回顾或索引都不得暗示删除原件。

## 12. 质量指标与评测

### 12.1 用户结果指标

上线前先建立基线，再为以下指标设置版本目标：

- 首次添加资料完成率和耗时；
- 首次进入后能说明“这里可以拿资料做什么”的用户比例；
- 从表达目的到得到第一个可用结果的完成率和耗时；
- 首次提问得到可引用回答的比例；
- 零结果和“依据不足”比例；
- 引用打开率及来源变化率；
- 结果被继续追问、保存、转任务或执行的比例；
- 创建任务后仍保持正确资料范围的比例；
- 一周内再次使用专题的比例；
- 主动建议关闭率和误打扰反馈。

不以“AI 回答次数”或“索引资料总量”单独作为成功指标。

### 12.2 检索评测

建立不包含真实敏感内容的代表性夹具，至少覆盖：

- 精确标题、文件名、发件人和正文短语；
- 同义表达和模糊时间描述；
- 多来源综合问题；
- 来源冲突；
- 缺失、变化、截断、扫描件和低置信 OCR；
- 跨项目、跨租户和未授权候选；
- 中英文混合资料。

语义层上线门禁：

- 不能降低关键词基线的 top-5 recall 和 MRR；
- 引用正确率必须单独测量，不能只测回答流畅度；
- 关闭语义层后功能可用且结果可解释；
- 模型或嵌入版本变化创建新索引版本；
- 评测失败时能按功能开关回退。

### 12.3 普通用户验收

- 用户无需解释即可说出至少三件 AI 能用资料完成的事；
- 用户能直接表达目的，也能从资料卡开始处理；
- 用户无需解释即可找到“添加资料”和“问问这些资料”；
- 用户能说明当前问题会读取哪些资料；
- 用户能从回答打开至少一个准确来源；
- 用户能把回答转成只携带选定引用的任务；
- 用户能分辨删除专题与删除原件；
- 用户知道主机命令、发布和删除不会在资料页静默执行；
- 390 px 页面可完成添加、提问、核验和创建任务；
- 模型不可用时仍能搜索、预览、定位和用于任务。

测试时禁止先向用户解释“知识库、RAG、索引或 Agent”。如果用户必须理解这些概念才能完成任务，视为设计失败，不归因于用户学习成本。

## 13. 分阶段开发计划

开发顺序按“用户可得到的结果”排列，不按底层技术排列。每个里程碑都必须可以单独发布、关闭和回退。

| 里程碑 | 用户得到的能力 | 主要复用 | 建议规模 | 依赖 |
| --- | --- | --- | --- | --- |
| M0 普通用户原型 | 看懂可以做什么，并完成一次模拟流程 | 现有资料页面与真实夹具 | 1 个设计 PR | 无 |
| M1 问资料 | 对现有资料提问、核验来源、创建任务 | 搜索、预览、受控读取、任务引用 | 4 个代码 PR | M0 |
| M2 生成结果 | 总结、提取、比较、生成草稿并保存版本 | M1 会话和引用 | 3 个代码 PR | M1 |
| M3 继续行动 | 将结果转成任务、站点草稿或主机操作预案 | 任务、我的站点、我的主机 | 3 个代码 PR | M2 |
| M4 添加与整理 | 添加文件/文字/图片/链接，加入专题 | 内容身份和原件管理 | 3-4 个代码 PR | M1，可与 M2 后半并行 |
| M5 看懂更多资料 | OCR、页码引用、可选混合检索 | 解析与评测框架 | 2-3 个代码 PR | M1、M4 |
| M6 回顾与扩展 | 周回顾、音视频、外部只读 AI | 所有已验证合同 | 分开立项 | 使用证据 |

### M0 — 普通用户减法评审与原型

交付：

- 桌面和 390 px 的首屏、范围选择、工作会话、引用预览、创建任务确认原型；
- 空资料、正常回答、资料不足、来源冲突、来源变化、模型不可用六种状态；
- 四组脱敏资料夹具和至少十二个带标准答案的问题；
- 五名不了解索引/RAG 的体验者完成任务记录；若暂时没有外部体验者，先由项目成员按无讲解脚本交叉测试。

退出门禁：80% 体验者能在 30 秒内说出至少三件可完成的事；无需解释即可发起问题；所有人都能找到引用和创建任务；没有技术状态占据首屏。

### M1 — 用现有资料得到可信答案

范围：

- 新增 `MaterialWorkSession`、消息和引用持久化；
- 接通现有有界检索和读取服务，不新建第二套检索；
- 首页目的输入、资料卡入口、选中资料入口和会话页面；
- 直接回答、资料不足、冲突、来源变化、取消和模型失败；
- 从回答创建只携带已确认引用的任务；
- 功能开关关闭时保持当前“我的资料”搜索与预览功能。

明确不做：Embedding、OCR、自动收纳、主动推荐、主机命令、站点发布和后台读取全部磁盘。

退出门禁：现有 `article`、`mail`、`task`、`task_input`、`task_output` 五类内容完成“提问—查看原文—创建任务”端到端测试；越权候选和未读取资料无法成为引用；取消后没有继续读取事件。

### M2 — 生成并保留可用结果

范围：

- 上线“帮我总结、提取信息、对比分析、整理成内容、安排下一步”模板；
- 使用统一结构化输出和引用校验，不为每个模板复制一套检索逻辑；
- 保存 Markdown 结果及版本，保留用户目的、引用和来源状态；
- 支持继续追问和基于上一版修改；
- 防止临时回答、保存结果和执行副本形成自动重复索引。

退出门禁：四组夹具的结构化字段完整；比较结果能区分“资料未提及”和“明确没有”；保存结果不覆盖原件；旧版本和引用仍可查看。

### M3 — 从结果继续推进工作

范围：

- `ActionProposal` 预览、确认、幂等执行和过期处理；
- 创建任务时预填目标、产物、选定引用和必要/参考用途；
- 创建“我的站点”草稿，不直接发布；
- 生成“我的主机”只读检查或变更预案，不在资料会话中直接执行；
- 执行完成后把状态和结果链接返回原会话。

退出门禁：未经确认不产生写入；重复确认不产生重复任务或草稿；资料范围在跨产品跳转后不扩大；主机、站点和删除类动作继续使用各自审批与审计。

### M4 — 统一添加资料与专题

范围：

- 文件/文件夹显式注册；
- 文字和图片的应用管理本地原件；
- 复用现有链接文章导入；
- 专题、批量成员关系和保存视图；
- 明确“留在原位置”和“保存到本机”的交互；
- 补齐导出、移出列表和删除原件的不同边界。

退出门禁：新用户不创建项目或任务也能添加资料并立即处理；添加流程默认推荐下一步用途；删除专题不会删除资料；应用管理原件可以导出。

### M5 — OCR 与混合检索

范围：

- 图片和扫描 PDF 的本地或受控 OCR；
- OCR 置信度、页码/区域引用和失败恢复；
- 评测门禁后的可选语义重排；
- 命中原文定位和相似/重复内容建议；
- 索引版本、重建和完全关闭开关。

退出门禁：扫描资料可以从回答定位到原始页；低置信内容不会显示成确定事实；语义层不降低关键词基线，且关闭后问答仍可工作。

### M6 — 回顾、音视频与外部 AI

M6 不作为一个整体开发。周回顾、音视频转写、只读 MCP/CLI 分别根据 M1-M5 的真实使用证据立项。任何外部 AI 接入都必须复用相同内容身份、范围、引用和审计语义；写入、分享和删除仍需独立审批。

## 14. M1 推荐实现拆分

M1 是当前推荐的首个生产开发阶段，按以下堆叠顺序执行：

### PR 1 — 会话、范围和持久化合同

- 增加服务端会话、消息、引用模型和存储迁移；
- 实现创建、读取、取消会话的 API；
- 将 `all_visible`、`collection`、`selected` 规范化为不可变的本轮读取范围；
- 增加租户、用户、项目和内容身份的授权测试；
- 暂不调用模型，使用确定性夹具响应验证状态机。

验收：重启后会话可恢复；取消和并发修订有明确结果；任意内容 ID 注入无法越权。

### PR 2 — 检索、生成和引用校验

- 增加资料工作编排服务，复用 `local-content-catalog` 和有界读取能力；
- 建立模型适配器和可替换的测试假模型；
- 生成直接回答、资料不足和冲突三类结果；
- 校验引用必须来自本轮已读内容，并记录来源指纹和定位信息；
- 增加读取预算、取消传播、模型超时和审计事件。

验收：标准问题引用正确；模型伪造内容 ID 或路径会被拒绝；服务不可用时不伪装成资料答案。

### PR 3 — 意图优先的前端体验

- 重排“我的资料”首屏，新增目的输入和常用动作；
- 资料卡收敛为“打开、问问这份资料、接着处理”；
- 增加多选资料动作条和范围抽屉；
- 增加会话、流式状态、结构化回答、引用定位和恢复状态；
- 完成桌面、键盘和 390 px E2E。

验收：无讲解完成首页提问和资料卡提问；屏幕阅读器可感知生成状态；取消按钮真正终止服务端工作。

### PR 4 — 回答转任务的闭环

- 从回答生成 `create_task` 提案；
- 预览任务目标、引用和用途，确认后调用现有任务接口；
- 固定被确认引用的来源指纹，未选候选不进入任务；
- 增加幂等、部分失败、来源变化和返回原会话处理；
- 完成真实本地运行的端到端验证。

验收：重复点击只创建一个任务；任务只获得确认资料；来源变化时要求重新确认；关闭 AI 功能后原有资料加任务路径不退化。

## 15. 代码落点与工程约束

建议代码边界：

```text
apps/server/src/routes/material-work-sessions.mjs
apps/server/src/services/material-work-session-store.mjs
apps/server/src/services/material-work-orchestrator.mjs
apps/server/src/services/material-work-citations.mjs
apps/server/src/services/material-action-proposals.mjs

apps/web/src/features/material-work/
  material-work-composer.tsx
  material-scope-picker.tsx
  material-work-session.tsx
  material-answer.tsx
  material-citations.tsx
  material-action-proposal.tsx
```

现有 `apps/web/src/features/local-content/` 继续负责资料浏览、筛选、卡片和预览；新的 `material-work` 负责“拿资料做事”。两者通过内容 ID 和范围对象连接，避免让当前 `local-library-view.tsx` 继续膨胀。

服务端必须复用：

- `local-content-catalog` 的身份、搜索和租户隔离；
- `local-content-originals` 的安全读取和来源状态；
- `local-content-retrieval` 的读取预算与不可信内容边界；
- 现有工作事项和内容引用接口；
- 现有任务、主机和站点的审批、审计与执行链路。

新增功能开关至少分为 `materialWork.enabled`、`materialWork.savedOutcomes`、`materialWork.actionProposals` 和 `localContent.semanticRerank`，不能用一个总开关绑定所有阶段。

## 16. 测试与发布计划

### 16.1 自动化测试

- 单元测试：意图模板、范围规范化、状态机、引用校验、结果结构和提案幂等；
- 服务测试：租户隔离、读取预算、取消传播、模型超时、来源变化和审计；
- Web 测试：输入目的、选资料、查看引用、错误恢复、创建任务和无障碍状态；
- E2E：五类现有资料各一条主路径，另有冲突、资料不足、取消和移动端路径；
- 安全测试：Prompt 注入资料、伪造引用、绝对路径泄露、跨项目内容 ID 和重复确认。

### 16.2 灰度顺序

1. 开发夹具和假模型，仅供自动化；
2. 本地开发开关，使用脱敏资料；
3. 项目维护者真实本机资料验证；
4. 小范围普通用户体验，记录任务完成率；
5. 默认开启 M1，M2-M6 保持独立开关。

回退时只关闭资料工作入口；原有搜索、安全预览、原件定位和添加到任务继续可用。会话数据保留并可导出/删除，不因功能关闭而静默丢失。

### 16.3 每个 PR 的完成定义

- 有对应用户目的和普通用户文案；
- 有正常、空、失败、取消和权限不足状态；
- 有自动化测试和至少一条手工验收记录；
- 没有展示绝对路径、内部检索术语或未授权候选；
- 支持功能开关和明确回退；
- 更新本需求、产品流程和术语表；
- 未将下一里程碑的风险偷偷带入当前 PR。

## 17. 开发前必须关闭的问题

M1 采用以下默认决策，除非原型或安全评审给出反证：

1. 每轮生成创建一种只读 `material_answer` 运行，复用现有 provider 调度、取消、成本和审计；它不绑定工作事项，也没有文件写入、Shell、主机或站点工具。
2. 模型默认使用应用当前可用的资料处理助手；普通用户无需每次选择。无兼容助手时显示“AI 暂时不可用”，继续提供搜索和预览。
3. 首页“全部资料”只包含当前用户通过现有权限可见且已进入资料目录的内容，不扫描新目录；持续显示“从全部资料中查找”，允许用户在开始前改为选中资料。
4. 未保存会话本地保留 30 天；用户保存的结果和由其创建的任务不自动过期。会话页更多菜单提供删除，设置页提供批量清理和导出。
5. M1 的引用定位统一使用 `sourceFingerprint + plainTextOffset + excerpt`。文章、邮件、任务、PDF 和 Office 均先定位到安全预览中的提取文本；PDF 页码、Office 结构和图片区域定位在 M5 增强。
6. 创建任务时统一固定当前来源指纹；来源变化后显示差异并要求重新确认，不能静默跟随最新版。
7. 长期 CI 使用四组脱敏夹具：客户邮件与附件、文章与笔记、会议记录、任务输入与结果；每组至少覆盖直接答案、跨资料综合和资料不足，另加一组全局冲突题。

仍需在 M1 PR 1 合并前完成一次架构/安全评审，确认 `material_answer` 运行的工具白名单、模型输出结构、读取预算和会话清理任务。它们是实现核验项，不再作为需要普通用户选择的产品问题。

M2 之前再确定：结果原件目录、版本策略、Markdown 导出和循环索引抑制。M3 之前再完成主机与站点操作提案的安全评审。M4 之前再确定文件夹是一次性添加还是持续观察。OCR、语义、回顾和外部 AI 不阻塞 M1。

关闭顺序：先批准 M0 普通用户原型和 M1 API/引用合同，再开始 M1 PR 1；先用真实使用证据验证 M1，再批准 M2-M6 的生产范围。
