# iLink 普通用户 P0-P2 验收

> 更新时间：2026-08-25
>
> 当前基线：通用与专业普通口语意图 291/291；可复现 Channel 规划器回放基线 46/46。专业基线独立覆盖自然口语、行业简称、否定、已有成果、多实例、跨专业、内部草稿与外部提交分离以及发布安全。`pnpm eval:intent:channel` 默认运行脱敏规划器回放，也可追加状态快照路径回放已经人工纠正的真实 Channel 样本；它不替代经过消息导入、会话状态、确认和任务创建的黑盒验收。

目标：用户只用自然语言完成咨询、任务、补充、确认、排队、授权和结果交付，不需要知道任务 ID、Invocation、Issue、Bridge 或命令语法。

## 必跑场景

1. 发送“你好”：直接回复，不创建任务。
2. 发送“为什么发布失败？”：作为咨询回答，不创建正式任务。
3. 发送“只读取当前目录，列出 3 个文件，不要修改”：由受控本地文件能力直接返回相对文件名，不进入 Agent 队列；若本地读取暂不可用，才降级到受约束的只读 Agent 路径。
4. 连续发送任务说明和两条补充：合并成一个待确认草稿。
5. 在任务执行中发送“只看华东客户”：建立紧随当前任务的后续调整，不取消、不改写当前执行。
6. 重复发送同一任务：复用现有任务；旧的无执行“需要关注”副本自动归档。
7. 发送含糊短句：若 Bridge 可用则辅助分类；否则提出与上下文相关的澄清问题，不误建任务。
8. 发送图片、语音或文件：立即说明已收到的媒体类型，再整理任务理解。
9. 普通授权：微信回复“确认授权”可继续；高风险授权必须提示“打开 MyAgentTool → 审批中心”。
10. 长任务：排队、开始、等待补充、等待授权、完成和失败均主动通知；无新阶段时按策略限频报状态。
11. 结果发送失败：自动重试；最终失败后可回复“重发结果”。
12. 服务重启：恢复排队/执行关联，投递不重复，旧重复任务不重新出现。
13. 任务复盘：回复“查看依据”或“为什么这样做”，能看到目标、使用资料、完成标准和下一步；多任务时先要求选择任务。
14. 公众号草稿执行：文章包不完整时不启动；保存回执与本次文章不一致时显示“待核对”，不会误报完成；登录失效或结果不确定时分别引导扫码恢复或先核对草稿箱。
15. 多意图任务：发送“把今天编码整理成文章和图片，文章发公众号，图片发小红书”，创建共享编码摘要、文章、图片及各自发布任务；文章和图片可以并行，各平台只等待自己需要的内容。
16. 对应关系不清：发送“做文章和图片，发公众号和小红书”，只追问一次“哪些内容发到哪些平台”；确认前不创建发布任务，也不默认把全部内容发到全部平台。
17. 动态插入：文章执行中追加“再做一份客户汇报”，新任务独立创建；除非用户明确说“基于文章”或存在成品交接，否则两者互不等待。
18. 局部失败与取消：取消图片或令图片失败，不影响文章及只依赖文章的公众号任务；依赖图片的小红书任务只显示自己正在等待或受阻。
19. 按名称控制：用户可以直接说“取消图片”“小红书先不发”“继续做小红书发布”“先做文章”，无需查看或复制任务编号；名称对应多个任务时只询问具体选择。
20. 真实优先级：说“先做文章”后，同时更新普通用户队列与任务调度优先级；不能越过真实产物依赖，也不会中断已经执行的任务。
21. 成品换版：发布确认后若上游成品发生变化，旧确认摘要立即失效，移除旧输入文件并主动提示重新核对最新版本。
22. 运行时隔离：上游任务失败或取消时，只把依赖它的后代任务标记为受阻；工作目标总览明确显示进行中、等待成品、等待确认、局部受阻及不受影响的任务数量。
23. 动态调整预览：发送“文章改成 1500 字，图片不动”或“小红书改发视频”时，先展示新增、修改、取消、保持不变和连带影响；确认前不修改任务。
24. 过期预览保护：预览后目标任务开始、完成、换版或依赖变化，回复“确认调整”不得执行旧预览；系统应说明发生变化并生成一份新的可确认预览。
25. 复合调整补偿：新适配链只创建一部分时，清理本次新增任务并保留旧发布链；不得留下两套同时可执行的发布任务。
26. 调整幂等：重复发送“确认调整”不会重复创建、修改或取消任务；服务重启遇到创建阶段中断时，清理本次新增并保留原任务，遇到已有原任务变化时停止重复执行并提示查看进度。
27. 会话焦点：选择一次任务后，服务重启或跨多轮交流仍能理解“这个先停一下”“这个怎么样”；“当前进度”不得误判为任务指代。
28. 明确纠错：发送“不是文章，是视频”时，只把当前焦点切换到视频任务，不修改、合并或启动任何任务。
29. 统一目标摘要：Channel 进度和桌面普通视图使用同一摘要模型，均显示整体进度、最近调整、结果检查和唯一下一步；专业视图继续保留依赖、版本和证据。
30. 独立返工：结果检查未通过时不得把原任务伪装成完成；回复“按检查结果修改”创建独立返工任务，原结果和其他离散任务保持不变。
31. 跨职业验收：运行不少于 200 条普通口语回放，并单独运行脱敏 Channel 黑盒回放，覆盖内容创作、软件开发、商务协作、多意图、否定和最小澄清；任务边界准确率不低于 95%，误建任务率不高于 1%，澄清准确率不低于 95%。
32. 专业能力恢复：图片、漫画、口播或视频能力缺失时允许仅保存任务，但不得启动 AI；普通用户可以直接进入应用配置，返回后在原计划中重新检查，不用重新输入任务。
33. 直接成果负向验收：执行器即使返回成功，只要没有成果文件、格式不符、数量不足或内容指标不达标，任务必须保持阻塞并给出具体原因，不能进入“待审核”。
34. 桌面返工闭环：普通任务详情直接列出未通过项；点击“按检查结果创建返工任务”只创建一个独立任务，不覆盖原任务、不自动执行。重复点击复用同一返工；有真实旧成果时记录成果交接，没有成果时复用原资料但不伪造依赖。
35. 唯一下一步：工作目标摘要把结果返工、待处理、查看进度或等待原因投影为一个可点击动作；Channel 与桌面仍读取同一目标摘要事实，不要求普通用户判断任务图。
36. 多对象拆分：发送“分别分析北京和上海两份销售数据”“A合同和B合同分别审查”时，按对象生成独立任务并保留可读对象名称。
37. 多任务统一确认：一句话形成两个以上任务时，无需用户预先知道“先规划”口令；系统默认显示任务篮，确认前不创建任务。
38. 账号配置续接：发布请求因账号未连接而暂停后，用户在桌面完成连接并回复“已连接”，系统重新读取账号状态并恢复原请求，不要求重发整句话。
39. 桌面澄清续接：桌面任务创建遇到范围、平台或专业动作不清时，用户可在原方案下直接回答；补充答案与原请求共同进入最终任务合同。

## 自动验收命令

```bash
pnpm eval:intent
pnpm eval:intent:channel
pnpm eval:channel:blackbox
```

`eval:intent` 和 `eval:intent:channel` 检查规划器任务边界；`eval:channel:blackbox` 经过真实 Channel 会话服务，覆盖消息导入、连续澄清、任务篮确认、账号连接恢复、任务创建和外部操作门禁。真实站点发布回执和最终内容质量仍需在连接测试账号的发布验收中单独验证。

## 离散任务操作系统验收原则

- 工作目标只保存共同背景、资料和最终方向，不充当固定流程定义。
- 每个任务都对应用户明确表达的当前意图；系统不能因为模板或常见流程擅自创建下一步。
- 任务依赖必须能指出具体的成品交接。没有“生产什么、消费什么”的关系，就不能建立硬依赖。
- 同一份来源可供多个任务并行使用；共享来源本身不是串行依赖。
- 模板可以提出建议，但建议必须保持可选，不能偷偷转成任务。
- 新意图可以随时插入、取消或改优先级；局部变化不得无故重排整个工作目标。

## 通过标准

- 普通回复不出现内部任务 ID、Invocation、Issue、Allowlist 或命令说明。
- 明确、低风险且能力已覆盖的只读请求不再要求用户二次确认，也不会被判定为文件修改；结果不出现绝对路径、英文报告模板或内部运行信息。
- 模糊意图预检不与正式任务竞争 Bridge 执行资源，超时后立即降级。
- 运行中补充有清晰归属，且后续任务排在原任务之后。
- 桌面频道页默认只展示连接、工作位置、提醒、任务状态和交互记录；诊断信息按需展开。
- 高风险、文件应用和其他不可逆操作继续遵守桌面审批边界。
- 普通用户可以按需询问任务依据，不需要进入 Invocation、Evidence 或专业诊断页面。
- 体验指标可统计针对性澄清、明确只读、本地直达结果、重复任务处理、运行中补充、重试通知去重和媒体回执。
- 外部草稿任务的完成必须有可验证回执；“执行器返回成功”本身不作为普通用户可见的完成依据。
- 普通回执应直接说明哪些任务可独立开始、哪些任务在等待哪个成品、当前是否需要用户操作；不得要求用户理解任务图或内部产物类型。
- 任一硬依赖都通过任务计划合同的成品交接校验；无交接的依赖必须拒绝创建。
- 暂停和取消必须同步到底层任务执行策略，服务重启或自动调度复核后不能偷偷重新执行。
- 所有带真实依赖的任务在成品到达前显示“等待成品”，不能显示为普通排队，也不能提前占用执行器。
