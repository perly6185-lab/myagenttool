# myagenttool v0.1.0 — the measured-and-enforced delivery line

Release zero (#256): the first versioned release, cut to exercise the full L5
path once. Pre-1.0; the product is an agent control plane in active build-out
(M2/M3 era) — this release versions the **AI delivery operating system** around
it, which reached "measured, then enforced" on 2026-07-02.

## Highlights

### Maturity calibration and honest measurement

- `MATURITY_CALIBRATION.md`: the self-authored L0–L6 ladder is now anchored to
  external references (DORA, SWE-bench method, SLSA/SSDF), with the
  no-industry-standard frontier flagged explicitly.
- Every maturity level with instrumentation cites a measured number instead of
  a self-graded tick (`FULL_FLOW_AI_DELIVERY.md` status column).

### L4 capability gates (`ai:eval-heldout`, `ai:eval-subcap`)

- Held-out coding eval: 21 history-mined cases (SWE-bench base-commit
  structure), difficulty tiers, four bidirectionally-validated fail-to-pass
  probes, isolated-worktree production resolver, Claude Code adapter.
  Real baseline 87.5% (8-case snapshot).
- Sub-capability eval: PM brief (product-gate oracle), issue-creation apply
  gate (product behavior, 100% required), review evidence (planted-defect
  detection). Real readings 6/6 · 6/6 · 3/3; mock floors keep the sets honest.

### Metrics counters (`github:dora`, `github:backlog`, `github:governance`)

- DORA lead time + merge frequency + CI-green rate (with Actions fallback),
  backlog/evidence coverage (L1 gate met: 100%/100%/0 stale), and the L3
  governance reading (29.1% coverage / 56 bypasses — the honest gap that drove
  enforcement).

### Enforcement

- CI as a PR gate: `verify` + `eval-gates` required on `main` (strict,
  up-to-date), `enforce_admins` on — direct-to-main bypasses are impossible.
- `pr-governance` advisory check on every PR (promotion to required tracked in
  #243); CODEOWNERS (solo-safe).

### Scheduled real evals (local cron)

- Nightly subcap + weekly full held-out runs on the maintainer machine via the
  logged-in Claude CLI (no stored API keys); JSONL trend with set versions.

## Known limitations

- No deployable artifact: server/web/desktop remain local-demo (M0 loop);
  deploy target is docs-preview only. DORA change-failure-rate and recovery
  time are **not instrumented** (honestly reported) until a real target exists.
- L3 risk-evidence coverage is measured but not yet enforced (advisory phase;
  #243 tracks promotion).
- Real-eval trend has < 3 records; `--min-pass-rate` hardening waits on data
  (#250).

## Rollback notes

This release is a tag + metadata + tooling line; each component rolls back
independently and safely:

| Component | Rollback |
| --- | --- |
| Version/tag | `git revert` the release PR; delete tag + GitHub Release (`git tag -d v0.1.0 && git push origin :v0.1.0`, `gh release delete v0.1.0`) |
| CI enforcement | `pnpm ci:activate --deactivate` (stops runners); remove branch protection via repo settings if needed |
| pr-governance advisory | `gh workflow disable governance.yml` |
| Scheduled real evals | remove the two `eval-real-cron.sh` crontab entries; trend file is local-only |
| Eval harness / counters | plain code revert; no persisted state beyond gitignored evidence |

No data migrations, no deployed services, no user-facing runtime change — the
M0 demo loop is unaffected (`pnpm smoke:local` green at release cut).
